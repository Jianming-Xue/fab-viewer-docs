/etc/filebeat/filebeat.yml第 1 步 · 只改这一处

文件末尾的「输出」段 —— 每台机器唯一必改的地方，其余整份照拷。

###################### 输出 ###################### - output.logstash: - hosts: ["logstash-01:5044", "logstash-02:5044"] + output.logstash: + hosts: ["mes-ls-01:5045", "mes-ls-02:5045"] loadbalance: true ttl: 60s ↑ 多节点有几个写几个；端口必须与 logstash 侧 10-input.conf 同值
目的：让本机的日志有地方送。这行没改对，Filebeat 会一直重试、registry 不推进，而现场以为「采集在跑」。
$ filebeat test config / test output第 2 步 · 起服务前自检

落配置后先跑这两条 —— 它们会真的连一下，不用等服务起来看日志。

$ sudo cp filebeat.yml /etc/filebeat/filebeat.yml $ sudo vi /etc/filebeat/filebeat.yml # 改上面那行 hosts $ sudo filebeat test config -c /etc/filebeat/filebeat.yml Config OK $ sudo filebeat test output -c /etc/filebeat/filebeat.yml logstash: mes-ls-01:5045... connection... parse host... OK dns lookup... OK addresses: 10.20.30.61 dial up... OK talk to server... OK
目的：把「语法错」和「端口/网络不通」在起服务之前挑出来。两个 OK 就是通；dial up / talk to server 报错 ⇒ 端口写错或加工层没起。
$ systemctl status · ls -l registry第 3 步 · 起服务后验证

只有一条判据最重要：registry 的 mtime 在不在动。它是采集进度的唯一凭据。

$ sudo systemctl enable --now filebeat && systemctl status filebeat Active: active (running) since Tue 2026-09-22 10:10:03 CST $ ls -l --time-style=full-iso /var/lib/filebeat/registry/filebeat/ -rw-r--r-- 1 root root 4211 2026-09-22 10:14:03.144 meta.json ↑ 隔十几秒再看一眼，mtime 要往前爬 —— 在爬 = 真在采 $ sudo journalctl -u filebeat -n 20 Harvester started for file: /mes/prod/systemlogs/MESFABsrv.log ↑ 没有 ERR 就是干净
目的：一眼分开「没在采」和「在采但送不出去」—— mtime 不动 = 路径没匹配上；mtime 在动但加工层 events.in 不涨 = 送不出去（回第 2 步）。
