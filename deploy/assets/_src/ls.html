pipeline/*.conf第 1 步 · 只改这 2 行

本目录的 5 个 conf 里，只有这两行要按现场改，改完其余文件原样可用。

① pipeline/50-output.conf　第 16 行 —— 写到哪个 OpenSearch output { opensearch { - hosts => ["https://os-node-01:9200", "https://os-node-02:9200", "https://os-node-03:9200"] + hosts => ["https://mes-os-01:9200", "https://mes-os-02:9200", "https://mes-os-03:9200"] index => "%{[@metadata][index]}" document_id => "%{LOG_LINE_ID}" ↑ 节点有几个写几个；内网走 HTTP 就把下面那行 ssl => true 改成 false，并删掉两行证书校验
② pipeline/10-input.conf　第 12 行 —— 收哪个端口 input { beats { - port => 5044 + port => 5045 } } ↑ 5044 是默认值。别的系统的管道若已占，必须换；Filebeat 侧 hosts 必须同值
目的：去掉本链路对现场的最后一处假设 —— 往哪写（①）、从哪收（②）。这两行对了，加工层就没有需要现场定制的参数。
/etc/logstash/{pipelines.yml · logstash.yml}第 3 步 · 追加，不覆盖

现有实例是多系统共用的，所以要动的是「别人的文件」，规矩只有一条：只追加，绝不覆盖。

③ pipelines.yml —— 在文件末尾追加这一整段（别人的条目一个字不动） + - pipeline.id: mes-lines + path.config: "/etc/logstash-mes/pipeline/*.conf" + pipeline.workers: 4 + pipeline.batch.size: 500 + pipeline.ecs_compatibility: disabled + queue.type: persisted ↑ ecs_compatibility 必须 disabled：开着会补 ecs / host 元字段，而行索引模板是 strict，多一个字段整篇写入失败
④ logstash.yml —— 逐项确认，缺才加（这两项整实例生效，会让别的管道也受影响） + dead_letter_queue.enable: true + config.reload.automatic: true + config.reload.interval: 3s ↑ jvm.options 不用动：本管道的时间是显式按 +08:00 构造的，不吃 JVM 时区
目的：让本链路跑起来，同时不动别人的管道。加错地方的代价是别的系统一起停，所以这两处必须逐字核对再保存。
$ curl localhost:9600第 4 步 · 重启后验证

重启整个实例后（别的管道也会断几秒），看两件事：事件在不在流、有没有被拒。

$ curl -s localhost:9600/_node/stats/pipelines | jq '.pipelines["mes-lines"].events' { "in": 182456, "filtered": 182456, "out": 182456, ← out 与 in 持平 = 没在丢 "duration_in_millis": 128430 } $ ls -l /var/lib/logstash/dead_letter_queue/ total 0 ← 空 = 没有写入被拒的事件
目的：in 涨 / out 不涨 只有两种原因 —— 字段被 strict 拒了（去看 DLQ），或 OpenSearch 侧不可写（模板没装、认证错）。前者回第 1 步①，后者回存储层。
