## 二、配置表 `FabViewerMisc`

| 字段 | 说明 |
|---|---|
| `id` | 技术主键（全项目表规范） |
| `item` | 配置项名 —— **唯一索引**（一行一个配置项；接口层也以它定位，§五） |
| `description` | 描述 —— **纯文本**，不限字符格式；**长度 ≤ 4000**（多行文本域） |
| `category` | 分类 —— 下拉候选 = **本表 `distinct(category)`**（自举，不另立清单） |
| `value` | 配置值 —— **JSON**（类型系统见 §四；接口传入即入库格式，后端零转换） |
| `updatedAt` / `updatedBy` | 审计，保存时自动 |

与 2026-10-08 旧版的三处差异：`value` 支持 JSON；`item` 定唯一索引；**取消 `enabled`**（配置项的存在与否就是开关，不设停用态）。

## 三、页面逻辑（自上而下分区）

### 3.1 搜索区

| 项 | 口径 |
|---|---|
| 条件 | **仅一个 `Item` 输入框**，按 `item` 栏位**模糊匹配**（contains；与 Reason Config 的 `ruleName` 精确匹配不同） |
| 按钮 | `Search` → `GET /api/v1/sys_misc/page` 查第 1 页；不填 = 查全部（推定） |

### 3.2 表格区

| 项 | 口径 |
|---|---|
| 列（按序） | Item、Description、Category、Value、Last Updated Time、Last Updated User + **Action（最右固定）** |
| Description 列 | 显示描述文本，超长**省略号**截断 |
| **Value 列** | 按 **JSON 字符串**显示，超长**省略号**截断；**可点击** → 打开**详情弹框**展示完整 Value（只读，即三模式弹框的查看模式，§3.3） |
| Action | **修改**（打开修改弹框）、**删除**（**弹框确认后**调接口，弹框形态按 `05`） |
| 分页 | **每页 20**（不分档） |
| 添加入口 | **表格左下方添加按钮图标** → 打开新增弹框（弹框式，区别于 Reason Config 的内嵌表单） |

**保存后的行级行为（2026-10-10 定，全部局部更新、不重拉列表）**：

| 动作 | 行为 |
|---|---|
| 新增（点添加图标） | **表格第一行先插入一个空白行**（占位），新增弹框同时打开 |
| 新增保存成功 | 接口返回值**填充进该空白行**；取消 / 失败 ⇒ **移除空白行**（推定，恢复原表格） |
| 修改保存成功 | 接口返回值**直接覆盖该行内容** |
| 删除成功 | **直接删除该行** |

### 3.3 三模式复用弹框（查看 / 修改 / 新增同一组件）

上方固定三字段 + 下方 Value 结构化编辑（§四）：

| 字段 / 区域 | 查看 | 修改 | 新增 |
|---|---|---|---|
| Item | 只读 | **锁定**（定位键） | 必填；仅大小写字母 + 数字，长度 ≤ 255（推定） |
| Description | 只读 | 可改 | 必填；**多行文本域**，不限字符格式，**长度 ≤ 4000** |
| Category | 只读 | **可改**（2026-10-10 定） | 必填；**下拉 + 输入双模式**（combobox），候选 = 本表 distinct；仅大小写字母 + 数字，长度 ≤ 255（推定） |
| Value | 只读 | 可改（结构化编辑） | 必填（推定）；先选类型再编辑（§四） |

## 四、Value 类型系统与结构化编辑器（2026-10-10 定）

**Value 顶层恒为 JSON List**，按元素类型分三类：

| 类型 | 形态 | 约束 | 编辑器 |
|---|---|---|---|
| **单一值** | `[ x ]`（**长度恒为 1**） | x ∈ 数字 / 文本 / **布尔**（全系统唯一允许布尔的形态） | 类型自适应单值控件 |
| **纯文本** | `[ a, b, c ]`（多元素） | 元素 ∈ 文本 / 数字，**禁止布尔** | 行式列表（增删行） |
| **Map** | `[ { 键: 值 }, … ]` | **键 = 自由键**；**值 = JSON 且只能是「纯文本」型**（文本/数字数组、禁布尔）⇒ **深度封顶两层**（Map 的值不能再嵌 Map / 单一值） | 每行 = 键输入框 + 纯文本子列表编辑器（复用上行控件） |

- **形态识别：按内容自动判** —— 打开时解析 JSON：长度 1 ⇒ 单一值；多元素全标量（无布尔）⇒ 纯文本；元素为对象 ⇒ Map。
- **规模上限（2026-10-10 定）**：List **最多 100 项** —— 顶层与 Map 元素的值数组同限（防护值，后端一并校验）。
- **新增空列表**无从识别 ⇒ **先选类型**，选定后按类型渲染编辑器。
- `ip_list` 示例（Map 型）：`[ {"PROD": ["10.18.100.1","10.18.100.2"]}, {"PIRUN": ["10.18.200.1"]} ]`。

## 五、接口清单

外壳一律走**统一响应包**（`{ "success": true, "errCode": 0, "data": ... }`，模块 1 `01` §5.1）。

| # | 接口 | Method | 用途 |
|---|---|---|---|
| 1 | `/api/v1/sys_misc/page` | `GET` | 分页查询 |
| 2 | `/api/v1/sys_misc` | `POST` | 新增 |
| 3 | `/api/v1/sys_misc` | `PUT` | 修改 |
| 4 | `/api/v1/sys_misc` | `DELETE` | 删除 |

**1 · `page`（GET，URL 参数）**

入参:`pageIndex`、`pageSize`(每页 20)、`item`(**模糊匹配**,可空 = 全部)。

```json
{
  "totalPage": 1, "total": 2, "pageIndex": 1, "pageSize": 20,
  "contents": [
    { "item": "env_list", "description": "<描述文本>",
      "category": "global", "value": ["PROD", "PIRUN"],
      "updatedAt": "…", "updatedBy": "…" }
  ]
}
```

(`id` 不出参 —— 行键即 `item`;定位、增删改全走它。)

**2 · `POST`（新增）** 入参四字段：

```json
{ "item": "env_list", "category": "global", "description": "<描述文本>", "value": ["PROD", "PIRUN"] }
```

- `item` 冲突（唯一索引）⇒ 拒（错误码，不覆盖）；其余校验同 §3.3 / §四。
- 出参:`data` = **单条配置对象**（字段同 `contents[]` 条目）——页面第一行的空白行用它填充（§3.2，2026-10-10 定）。

**3 · `PUT`（修改）** 入参与 POST 完全一致（`item` 作定位键，虽不可改；`category` / `description` / `value` 为新值）。出参同 POST（单条对象，页面直接覆盖该行，§3.2）。

**4 · `DELETE`** 入参**仅 `item`**;出参只报成败。**前端须弹框确认后才调用**（§3.2）。

**value 的后端复验（推定）**：直调接口绕过页面编辑器时，后端按 §四同一套类型规则校验（单一值长度 1 / 纯文本禁布尔 / Map 值限纯文本），不符即拒 —— 防把坏结构写进全局配置。

## 六、与候选值接口的关系（2026-10-10 拍板：**候选值都从 Misc 出**）

模块 1/00 的跨模块依赖「环境名 / Host IP / Server Category 的候选值来自配置」——落点即本功能。六个 `/list` 候选接口的数据源全部为 Misc，`item` 命名约定：

| 候选接口 | 消费方 | Misc 的 `item` | Value 类型 |
|---|---|---|---|
| `GET /api/v1/env/list` | 01 / 02 / 03 的 Environment 下拉 | `env_list` | 纯文本 |
| `GET /api/v1/ipaddress/list?environment=` | 01 / 03 的 Host IP 下拉（环境联动） | `ip_list` | **Map**（键 = 环境名，值 = IP 数组）—— 联动即「按 `environment` 取键」 |
| `GET /api/v1/server_category/list` | 01 / 03 的 Server Category 下拉 | `server_category_list` | 纯文本 |
| `GET /api/v1/rule_result/list` | 01 折叠区 Rule Result 下拉 | `rule_result_list` | 纯文本 |
| `GET /api/v1/lock_object/list` | 01 列设置 Lock Object 候选 | `lock_object_list` | 纯文本 |
| `GET /api/v1/call_sys/list` | 01 列设置 Call Sys 候选 | `call_sys_list` | 纯文本 |

> `lock_object` / `call_sys` 在 04 的「开放集合、零配置」指**落库侧不设清单**（见到什么记什么）；下拉候选从 Misc 出只是**输入辅助**，不构成白名单 —— 两者不矛盾。候选取数即「按 `item` 读 Misc 的 `value`」。
