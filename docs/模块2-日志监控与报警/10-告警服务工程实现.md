# 告警服务 · 工程实现规格

> 模块 2 · 日志监控与报警 ｜ 告警通知定时器（应用 `monitor-alarm` 内 · 与功能 1 / 功能 2 同进程 · 独立节奏）｜ 状态：**定版**
> 本篇只讲一件事：把两张告警状态表里「未通知（未发）」的行捞出来，按组汇总、组稿、经邮件 / 飞书发出、回写状态。**判定怎么出、issue 怎么落不在这里** —— 关键字判定见 [`02`](02-MES关键字监控与告警.md)、Server Hang 判定见 [`04`](04-MES Server Hang 监控与告警.md)；通知怎么配见 [`01`](01-MES关键字监控配置.md) §2.2 / [`03`](03-MES Server Hang 监控配置.md) §2.2；报警怎么展示处置见 [`05`](05-MES关键字告警展示.md) / [`06`](06-MES Server Hang 告警展示.md)。

## 1. 功能定位

关键字监控（3min）、Server Hang 监控（3min）、本篇通知（1min）是**同一个应用 `monitor-alarm` 里的三个定时器**（同一进程、多定时器项目，见 `04` §5），各自一把 `FvTurn` 行锁、各自节奏、互不阻塞。前两个只负责**判**、把结果写进两张状态表 + OS 结果索引；**本篇是其中的通知定时器**，只负责**发**。这里的「独立」= 定时器 / 轮次锁 / 节奏独立，**不是独立部署** —— 三者同属 `monitor-alarm`。

- **单实例节奏**：固定 1min 触发；一轮（含邮件 / 飞书外发）没跑完，下一刻度到点直接跳过，直到本轮处理完毕 —— 不排队、不补跑、不并发。
- **服务对象两类、四段**：关键字状态表一段；Server Hang 状态表按 `IssueType` 分三段 —— `Server Hang` / `Endless Rule` / `Rule Recovered`。
- **一句话循环**：每 1min 醒一轮 → 扫两张表捞未发行 → 按组分类 → 每组查配置、判间隔 → 到期就组稿发邮件 / 飞书 → 成功回写 `Alarmed=true`、`LastAlarmTime=now`。
- **本篇只定义通知侧机制** —— 捞取条件、分组键、间隔判定、组稿格式、通道成功口径、回写字段。配置字段的定义在 `01` / `03`，issue 与状态行的产生在 `02` / `04`。

## 2. 数据源（读什么、回写什么）

**两张告警状态表**（通知服务读 + 回写，表结构定义在 `02` §2.1 / `04` §2.1，本篇不复述）：

| 表 | 捞取用的列 | 回写用的列 |
|---|---|---|
| `FvLogMonitorAlarmState`（关键字） | `Item` / `Environment` / `Priority` / `Keyword` 来源见下 / `Alarmed` / `LastAlarmTime` | `Alarmed` / `LastAlarmTime` |
| `FvSrvHangMonitorAlarmState`（Server Hang） | `IssueType` / `Environment` / `Priority` / `Alarmed` / `LastAlarmTime` | `Alarmed` / `LastAlarmTime` |

**配置链**（只读，定义在 `01` §2.1 / §2.2、`03` §2.1 / §2.2）：

- 关键字：组键 `Item + Environment` → `FvLogMonitorCfg`（唯一索引 `Item+Environment`）→ `AlarmCfgId` → `FvAlarmCfg`。**Keyword 取该配置行的 `Keyword`** —— 一组 = 一条配置 = 一个关键字，天然单一。
- Server Hang 三段：组键 `Environment` → `FvSrvHangMonitorCfg`（唯一索引 `Environment`）→ `AlarmCfgId` → `FvAlarmCfg`。三段共用同一环境一份配置。
- 通知配置 `FvAlarmCfg` 用三样：`MailToUsers`（空⇒邮件不发）、`FeishuGroups`（JSON map，空⇒飞书不发）、`NotifyInterval`（分钟，`2 ~ 99999`）。
- **配置查不到、或主配置 `Enabled` 非 `true`（`0` / `NULL` 一律算未启用）⇒ 该组不发通知，直接回写 `Alarmed=true`、`LastAlarmTime=now`**（与停用规则口径一致，防每组每轮空转）。

**组稿要补的字段**（状态表里没有，按 `BlockId` 回 OS 块文档取，见 §5.3）。

## 3. 定时器与互斥

| 项 | 口径 |
|---|---|
| 应用归属 | 与 `02`（`MONITOR`）/ `04`（`SRVHANGMON`）同属应用 **`monitor-alarm`** —— 同一进程三个独立定时器、各占一把 `FvTurn` 行锁；本篇是第三个（`ALARMNOTIFY`），应用形态见 `04` §5 |
| 触发间隔 | **1min**，固定在整分钟触发；与关键字 / Server Hang 两个 3min 定时器各自节奏、互不阻塞 |
| 跨机互斥 | 轮次表 `FvTurn` **独立行 `Name='ALARMNOTIFY'`** + `SELECT … FOR UPDATE SKIP LOCKED`；与 `MONITOR` / `SRVHANGMON` 各占一行、各一把锁、互不阻塞 |
| 抢不到锁 / 上轮没完 | 别人在跑 ⇒ 本轮整轮跳过、不排队、不补跑；**本轮执行超过 1min、跨过下一刻度 ⇒ 该刻度自动跳过，直到本轮处理完毕**（进程内「正在跑就跳过本次触发」防同机重入、不并发） |
| 事务边界 | 抢锁 → 捞行 → 发邮件 / 飞书 → 回写 `Alarmed` / `LastAlarmTime` → `COMMIT` 全在一个事务里；**外部发送在锁内、提交前**（回写与发送必须同事务，否则发出去却没回写会重复发） |
| 崩溃 | Oracle 行锁随事务回滚自动释放，下一轮别的节点接管；已发出的外部消息无法回滚，靠 §4 的捞取条件 + 回写兜幂等 |

**每轮锁 SQL**（行由初始化脚本 / 运维预置，服务启动只校验存在、不写）：

```sql
-- ① 抢轮次（跨机互斥，必须带 SKIP LOCKED）
SELECT Name FROM FvTurn WHERE Name = 'ALARMNOTIFY' FOR UPDATE SKIP LOCKED;
-- 返回 1 行 = 抢到；0 行 = 别人在跑，本轮结束

-- ② 整轮捞取 + 发送 + 回写成功后，同事务提交
COMMIT;
-- 任一失败：ROLLBACK，通知可不发、状态不回写，下轮靠未发条件重新捞
```

> 启动校验：连不上 / `ALARMNOTIFY` 行缺失 / 查不动 ⇒ 直接启动失败报错，不降级、不自动补行（与 `02` §5.2 同口径 —— 行缺失会伪装成「每轮都被跳过」⇒ 静默全停）。

## 4. 捞取、分组与间隔判定（四段）

一轮内**顺序跑四段**：先扫关键字表（§4.1），再扫 Server Hang 表按 `IssueType` 跑三段（§4.2 ~ §4.4）。每段内部都是「捞未发行 → 按组键分组 → 逐组查配置 / 判间隔 → 到期组稿发送 → 成功回写」。

### 4.1 第一段 · 关键字（`FvLogMonitorAlarmState`）

| 步 | 口径 |
|---|---|
| 捞取 | `Alarmed` 非 `true` 的全部行 |
| 分组 | 按 `Item + Environment` 分组；组键同时用于查 `FvLogMonitorCfg` |
| 取配置 | 每组按 `Item + Environment` 查规则 → `AlarmCfgId` → `FvAlarmCfg`；查不到 / 规则 `Enabled` 非 true ⇒ 直接回写整组 `Alarmed=true`、`LastAlarmTime=now`，不发 |
| 间隔 | 有配置 ⇒ 从本组里取 `Alarmed=true` 行的**最大 `LastAlarmTime`**；用 `now − 该时间` 得分钟差，与 `NotifyInterval` 比：**小于不发，≥ 就发**。**组内一条 `Alarmed=true` 都没有（首次）⇒ 直接发** |
| 发送 / 回写 | 见 §5 组稿、§6 通道判定；成功后整组所有行 `Alarmed=true`、`LastAlarmTime=now` |

### 4.2 第二段 · `Server Hang`（`FvSrvHangMonitorAlarmState`）

| 步 | 口径 |
|---|---|
| 捞取 | `IssueType='Server Hang'` 且 `Alarmed` 非 `true` 的行 |
| 分组 | 按 `Environment` 分组（同一环境一份 `FvSrvHangMonitorCfg`） |
| 取配置 | 按 `Environment` 查配置 → `AlarmCfgId` → `FvAlarmCfg`；查不到 / `Enabled` 非 true ⇒ 直接回写整组 `Alarmed=true`、`LastAlarmTime=now`，不发 |
| 间隔 | 同 §4.1：组内 `Alarmed=true` 的最大 `LastAlarmTime` 比对 `NotifyInterval`；无已发行（首次）⇒ 直接发 |
| 发送 / 回写 | 成功回写整组 `Alarmed=true`、`LastAlarmTime=now` |

> `Server Hang` 行**没有 `Rule Recovered` 态**（`04` §7.6）：恢复后再犯记新行、旧行不动。本段只处理 `IssueType` 恒为 `Server Hang` 的行。

### 4.3 第三段 · `Endless Rule`

| 步 | 口径 |
|---|---|
| 捞取 / 分组 / 取配置 | 完全同 §4.2，只是 `IssueType='Endless Rule'` |
| 间隔 | 同 §4.2 |
| 发送 / 回写 | 成功回写 `Alarmed=true`、`LastAlarmTime=now` |

> 重复命中的 Endless Rule 天然幂等（`_id` 恒定、落库以第一次为准，`04` §7.6），状态表只有一行，本段不会重复发。

### 4.4 第四段 · `Rule Recovered`（特殊段）

恢复行由 `04` §7.6 在块闭合时原位改出：Oracle `IssueType` 从 `Endless Rule` → `Rule Recovered`、`Alarmed` 从 true 改 false、`LastAlarmTime` **不变**、同时写 resolved 三列（`System` 自动处置）。本段捞的就是这类行。

| 步 | 口径 |
|---|---|
| 捞取 | **三条同时满足才捞**：`IssueType='Rule Recovered'` **且** `Alarmed=false` **且 `LastAlarmTime` 非空**。`LastAlarmTime` 为空（从没报过就恢复）⇒ 不发 |
| 分组 / 取配置 | 同 §4.2，按 `Environment` 查 `FvSrvHangMonitorCfg` → `FvAlarmCfg`；查不到 / 未启用 ⇒ 直接回写 `Alarmed=true`、`LastAlarmTime=now`，不发 |
| 间隔 | **不看 `NotifyInterval`、不比对时间差 —— 只要捞到就发**（因为 `LastAlarmTime` 是上次 Endless Rule 报警时刻，比对间隔会把恢复通知压掉） |
| 原始报警时间 | 组稿前先取出**修改前的 `LastAlarmTime`** 作 `Endless Rule Alarm Time`（§5.2），**必须在回写把它刷成 `now` 之前取** |
| 发送 / 回写 | 成功回写 `Alarmed=true`、`LastAlarmTime=now`（改完不再满足捞取条件，不会重复发）；失败不回写、下轮再捞 |

**捞取条件对比**（`LastAlarmTime` 在两类里作用相反，别记混）：

| 段 | `Alarmed` | `LastAlarmTime` | 间隔 |
|---|---|---|---|
| 关键字 / Server Hang / Endless Rule | 非 `true` | 空 = 首次 ⇒ 直接发；非空 ⇒ 比对间隔 | 比对 `NotifyInterval` |
| Rule Recovered | `false` | **必须非空**（= 之前真报过 Endless Rule）⇒ 才发 | **不比对**，有就发 |

### 4.5 捞数据的 SQL 与 DSL

捞未发行在 Oracle（状态表是主数据源），组稿缺的列回 OS 补 —— **SQL 只捞 + 判间隔 + 回写，DSL 只补字段**，按下面写一次，不在别处另起一套。

#### 4.5.1 Oracle · 捞未发行、间隔判定与回写

**① 捞未发行**（四段各一条，按 §4.1 ~ §4.4 顺序跑；走 `(Alarmed, LastAlarmTime)` 辅助索引，`1` = 底层控制的 `NUMBER(1)` 布尔 true）：

```sql
-- 第一段 · 关键字
SELECT LineId, Item, Environment, Priority, RuleName,
       IssueTime, ReportTime, Alarmed, LastAlarmTime
  FROM FvLogMonitorAlarmState
 WHERE NVL(Alarmed, 0) <> 1              -- 非 true（0 / 空）即未发
 ORDER BY Environment, Item, ReportTime;

-- 第二段 · Server Hang
SELECT IssueId, IssueType, Environment, Priority, RuleName,
       IssueTime, ReportTime, BlockId, Alarmed, LastAlarmTime
  FROM FvSrvHangMonitorAlarmState
 WHERE IssueType = 'Server Hang' AND NVL(Alarmed, 0) <> 1
 ORDER BY Environment, ReportTime;

-- 第三段 · Endless Rule（同上，IssueType 换 'Endless Rule'）
SELECT IssueId, IssueType, Environment, Priority, RuleName,
       IssueTime, ReportTime, BlockId, Alarmed, LastAlarmTime
  FROM FvSrvHangMonitorAlarmState
 WHERE IssueType = 'Endless Rule' AND NVL(Alarmed, 0) <> 1
 ORDER BY Environment, ReportTime;

-- 第四段 · Rule Recovered（两个附加条件缺一不可）
SELECT IssueId, IssueType, Environment, Priority, RuleName,
       IssueTime, ReportTime, BlockId, Alarmed, LastAlarmTime
  FROM FvSrvHangMonitorAlarmState
 WHERE IssueType = 'Rule Recovered'
   AND Alarmed = 0                       -- false
   AND LastAlarmTime IS NOT NULL         -- 之前真报过 Endless Rule
 ORDER BY Environment, ReportTime;
```

**② 取组内上次通知时刻**（有配置的组才查、一组一条；查无行 = `NULL` = 首次 ⇒ 直接发；Rule Recovered 段不查、按 §4.4 直接发）：

```sql
-- 关键字组（组键 Item + Environment）
SELECT MAX(LastAlarmTime) AS LastAlarmTime
  FROM FvLogMonitorAlarmState
 WHERE Item = :item AND Environment = :env AND Alarmed = 1;

-- Server Hang / Endless Rule 组（组键 IssueType + Environment）
SELECT MAX(LastAlarmTime) AS LastAlarmTime
  FROM FvSrvHangMonitorAlarmState
 WHERE IssueType = :issueType AND Environment = :env AND Alarmed = 1;
```

**③ 成功回写**（同事务、整组一起提交；`Alarmed` 是底层控制字段，由底层通知回写入口置 `1`，下面 SQL 表达该入口的落库效果，业务侧不另行维护此字段）：

```sql
-- 关键字组：按业务 UK LineId + Item 定位
UPDATE FvLogMonitorAlarmState
   SET Alarmed = 1, LastAlarmTime = :now
 WHERE LineId = :lineId AND Item = :item;

-- Server Hang 三段：IssueId = OS _id、业务 UK
UPDATE FvSrvHangMonitorAlarmState
   SET Alarmed = 1, LastAlarmTime = :now
 WHERE IssueId = :issueId;
```

> `:now` 一组取一次、整组同一值；④ Rule Recovered 的 `Endless Rule Alarm Time` 必须在执行 ③ 回写之前从 `LastAlarmTime` 取出（§4.4 / §5.2）。

#### 4.5.2 OS · 补字段的 DSL

**哪段跳哪几跳**（状态表没有的才回 OS；`Rule Name` / `Issue Time` 用状态表快照、不回 OS）：

| 段 | ① 结果索引（`issueMessage` / `blockId`） | ② 块索引（`HOSTIP` / `SERVER_ID` / `TID`） |
|---|---|---|
| 关键字 | 要 —— `issueId = LineId\|Item`；状态表没 `BlockId`，`blockId` 只能从这跳拿 | 要 —— 用①的 `blockId` |
| Server Hang | 要 —— 取表格里的 `Issue Message` | 要 —— 状态表已有 `BlockId` |
| Endless Rule | **不要** —— 表格无 `Issue Message` 列，`BlockId` 状态表已有 | 要 |
| Rule Recovered | **不要** —— 同上 | 要 |

**第 1 跳 · 结果索引**（`mes-log-monitor-issue-{yyyy.MM}`，按 Oracle 行的 `IssueTime` 月份定索引，`09` §五）：

```json
GET /mes-log-monitor-issue-2026.11/_search
{
  "size": 200,
  "track_total_hits": false,
  "_source": ["issueMessage", "blockId"],
  "query": {
    "ids": {
      "values": [
        "PROD_10.20.30.40_3f2a9c1d0b7e4f68_8012000_20261123101530001|JOBPREPRULE",
        "PROD_10.20.30.40_3f2a9c1d0b7e4f68_8012000_20261123101530001|Server Hang"
      ]
    }
  }
}
```

**第 2 跳 · 块索引**（`mes-log-exec-{yyyy.MM.dd}`，按 `blockId` 末段 17 位毫秒串的日期定索引）：

```json
GET /mes-log-exec-2026.11.23/_search
{
  "size": 200,
  "track_total_hits": false,
  "_source": ["HOSTIP", "SERVER_ID", "TID"],
  "query": {
    "ids": {
      "values": [
        "PROD_10.20.30.40_FABsrv.10_PROD_10.20.30.40_3f2a9c1d0b7e4f68_8012000_20261123101530001"
      ]
    }
  }
}
```

- 两跳都用 `ids` 按 `_id` 精确取：不搜关键字、不排序、不算分、不带 `sort`；回填按 `_id` 建 map，OS 返回顺序不保证。
- 索引名是去 `prefix` 的基名，实际由框架前置环境段（`09` §五）；一次捞取跨月 / 跨日 ⇒ 按索引名分组、一组一次请求。
- `TID` 是 keyword 可多值、**取数组首个**（对齐 `06` §4.2）；`issueMessage` 是 text 字段、`_source` 直取原文。
- 块已过 360 天保留期回不到 ⇒ 这几列留空、通知照发（§8）。
- 与 `05` / `06` 的三跳是**同一套查询的前两跳**，索引选择规则不另起；通知侧不需要第三跳行索引 —— 表格的 `Issue Message` 就是结果索引里存好的原文，不是块首行 `LOG_BODY`。

## 5. 发送内容

**邮件 = HTML 表格，飞书 = Markdown 表格；表格列两者完全一致**（只是渲染不同）。**飞书在表格消息前把邮件 Subject 加粗置顶**（同一句 Subject 两处复用）。一组一条消息：邮件一封、飞书每个群一条（§6.2）。**所有固定文字与表头走 i18n 中英文词条**（§5.5）。

### 5.1 Subject 模板

| 段 | Subject | 取值 |
|---|---|---|
| ① 关键字 | `[等级] MES {环境}: 关键字 {Keyword} 报警` | 等级 = 配置 `Priority`；环境 = 组 `Environment`；Keyword = 配置的 `Keyword` |
| ② Server Hang | `[等级] MES {环境}: Server Hang报警` | 等级 / 环境同上 |
| ③ Endless Rule | `[等级] MES {环境}: Endless Rule报警` | 同上 |
| ④ Rule Recovered | `[等级] MES {环境}: Rule Recovered报警` | 同上 |

> 中英文两套模板都进 i18n（§5.5）：`关键字` ↔ `Keyword`、`报警` ↔ `Alarm`，`Server Hang` / `Endless Rule` / `Rule Recovered` 两语言原样保留。`[等级]` 用半角方括号，`MES {环境}:` 后按模板给一个空格。

### 5.2 表格列

| 段 | 列（顺序固定，两者一致） |
|---|---|
| ① 关键字 | Host IP · Rule Name · Issue Time · Issue Message · TID |
| ② Server Hang | Host IP · ServerID · Rule Name · Issue Time · Issue Message · TID |
| ③ Endless Rule | Host IP · Rule Name · TID · ServerID |
| ④ Rule Recovered | Host IP · Rule Name · TID · ServerID · **`Endless Rule Alarm Time`** |

- ④ 的 `Endless Rule Alarm Time` = **修改前的 `LastAlarmTime`**，即上次 Endless Rule 报警时刻（不是恢复时刻、不是 `ReportTime`）。
- ③ 没有 Issue Time / Issue Message 列：B（Endless Rule）的 `issueMessage` 本就写空串（`04` §3），表里不放这两列。

### 5.3 字段来源

| 列 | 来源 | 备注 |
|---|---|---|
| Host IP | OS 块文档 `HOSTIP` | 按 `IssueId`/`BlockId` 回 `mes-log-exec-*` 取（状态表里没有） |
| ServerID | OS 块文档 `SERVER_ID` | 同上 |
| TID | OS 块文档 `TID` | **keyword 可多值，取数组首个**（对齐 `06` §4.2） |
| Rule Name | 状态表 `RuleName`（块 `RULENAME` 首值快照） | 单值 |
| Issue Time | 状态表 `IssueTime` | 命中时刻；③④不放此列 |
| Issue Message | OS 结果索引 `issueMessage` | 关键字 = 命中行 `LOG_BODY`；Server Hang ② = 当时 `END_LINE_ID` 行原文；③ = 空串、表里不放 |
| Endless Rule Alarm Time | 修改前的 `LastAlarmTime` | 仅④；回写前取（§4.4） |

> 同一组多行按 `BlockId` 去重后回块取 Host IP / ServerID / TID —— 具体 SQL / DSL、哪段跳哪几跳、索引名怎么算见 §4.5（只走 `05` / `06` 三跳的前两跳，无第三跳行索引）；回不到（块已过保留期）就留空，不阻断发通知。

### 5.4 邮件 / 飞书通道口径

**邮件**

- `MailToUsers` 为空 ⇒ **邮件不发**（不发送视为该通道成功）；CC 不顶替 To。
- `MailToUsers` 非空 ⇒ 发送，To 为主送、CC 为抄送；发送结果按通道返回判定。

**飞书**（配置 `FeishuGroups`：key = 群 webhook、value = 该群 @ 的人 open_id，单值 string / 多值 string[]）

- `FeishuGroups` 为空 ⇒ **飞书不发**（不发送视为该通道成功）。
- 非空 ⇒ **逐 key 各发一条**，各自 @ 该 key 下的人；**一个群失败不影响下一个群**，某群失败重试一次、仍失败只记日志、不阻断其他群。
- **只有全部群都失败才算飞书发送失败**，此时**记一条日志**（§6.3）。

**成功判定**

| 情形 | 该组结果 |
|---|---|
| 邮件 / 飞书都不需发（都没配） | 视为成功，回写（配了通知表但两通道都空 = 只落库不发，同 §2 的吞掉口径） |
| 邮件、飞书**都有发送行为** | **只要任一类型成功即整组成功** ⇒ 回写 |
| 只有一种通道有发送行为 | 该通道成功 ⇒ 整组成功；该通道失败 ⇒ 整组失败 |
| 两通道都有发送行为且都失败 | 整组失败 ⇒ 不回写、记日志、下轮重发 |

### 5.5 i18n 词条

Subject 模板与表头全部做成中英文词条，运行期按当前语言取。至少要覆盖：

| 词条用途 | 中文 | English |
|---|---|---|
| Subject · 关键字 | `[等级] MES {环境}: 关键字 {Keyword} 报警` | `[{priority}] MES {environment}: Keyword {keyword} Alarm` |
| Subject · Server Hang | `[等级] MES {环境}: Server Hang报警` | `[{priority}] MES {environment}: Server Hang Alarm` |
| Subject · Endless Rule | `[等级] MES {环境}: Endless Rule报警` | `[{priority}] MES {environment}: Endless Rule Alarm` |
| Subject · Rule Recovered | `[等级] MES {环境}: Rule Recovered报警` | `[{priority}] MES {environment}: Rule Recovered Alarm` |
| 表头 | Host IP / ServerID / Rule Name / Issue Time / Issue Message / TID / Endless Rule Alarm Time | 同左（服务端 Hang 三类名保留英文；Issue Time / Issue Message / Rule Name / Endless Rule Alarm Time 按需给中文对应） |

> `{环境}` / `{Keyword}` / `{等级}` 为运行期占位符，不进翻译。表头英文沿用展示层 `05` / `06` 已有的出参命名，避免同一列两处两套词。

## 6. 回写与失败处理

### 6.1 回写（成功）

整组发送成功后，同事务内对该组**全部行**写：

| 字段 | 值 |
|---|---|
| `Alarmed` | `true`（库中 `1`） |
| `LastAlarmTime` | 当前系统时间（一次取值、整组同一值） |

- 关键字组 = 该 `Item+Environment` 下本轮捞到的全部行；Server Hang 三段 = 该 `Environment` + 该 `IssueType` 下本轮捞到的全部行。
- §4.2 的吞掉分支（配置查不到 / 未启用）也用这两个值回写，只是不发通知。
- ④ Rule Recovered 的 `Endless Rule Alarm Time` 必须在回写前取（§4.4）。

### 6.2 回写与重试（失败）

- 发送失败（通道判定失败）⇒ **不回写**、`Alarmed` 保持非 `true`、`记日志`，`ROLLBACK`。
- 下一轮按 §4 的捞取条件重新捞到 ⇒ 再发。关键字 / Server Hang / Endless Rule 下轮仍受间隔判定约束（`LastAlarmTime` 没推进）；Rule Recovered 下轮照捞（false + 旧 `LastAlarmTime` 非空）。

### 6.3 日志

| 场景 | 记什么 |
|---|---|
| 飞书全群失败 | 一条日志（组键 + 失败群数 / 原因） |
| 邮件发送失败 | 一条日志（组键 + 失败原因） |
| 单群失败但其他群成功 | 该群一条（不阻断）；整组仍算成功 |
| 配置查不到 / 未启用被吞掉 | 按组记一条（组键 + 原因），便于排查「为什么不通知」 |

## 7. 配置参数

本篇没有独立的应用参数表 —— 只读现成的：

| 参数 | 定义位置 | 本篇用途 |
|---|---|---|
| 定时器间隔 1min | 本篇固定 | 触发节奏（不进配置） |
| `NotifyInterval` | `01` §2.2 / `03` §2.2（`2 ~ 99999`、默认 5） | §4.1 ~ §4.3 的间隔比对 |
| `MailToUsers` / `FeishuGroups` | `01` §2.2 / `03` §2.2 | §5.4 通道是否需要发 |

## 8. 边界与已知代价

- **补字段可能留空**：块被 360 天清理后回不到块文档，Host IP / ServerID / TID 留空、通知照发（不阻断）。
- **事务里做外部 IO**：邮件 / 飞书在锁内、提交前。发送慢会拉长 `ALARMNOTIFY` 行锁持有时间 —— 一旦越过下一个 1min 刻度，该刻度直接跳过、不补跑，直到本轮处理完毕（§3 的 skip 语义）；若实测发送耗时过长，再评估「先标记发送中、发出后异步回写」的方案 —— 当前不做。
