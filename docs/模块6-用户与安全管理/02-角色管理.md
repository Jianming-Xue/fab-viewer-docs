# 角色管理 · Role

| 项 | 内容 |
|---|---|
| 模块 | 模块 6 · 用户与安全管理 · **角色管理** |
| 使用者 | IT 运维（角色维护）；前端全局（权限消费） |
| 状态 | 需求骨架（沟通中） |

> 权限的**组织者是前端**：菜单与按钮的路径注册表由前端代码内置（随版本演进）；本功能只负责勾选、存取、下发。后端对路径**不解析、不校验语义**，只当字符串集合。

---

## 一、功能定位

| 项 | 内容 |
|---|---|
| 干什么 | 角色 CRUD；为角色勾选**菜单权限**与**按钮权限**（路径集合，行内 JSON）—— 角色**只管功能访问权限**，登录策略不在角色上（策略直接挂用户，`01` §2.2） |
| 形态 | 配置页（角色列表 + 配置弹框）＋ Oracle 表 `FabViewerRole` |
| 权限生效 | 多角色用户 = 各有效角色 permissions 的**并集**；前端按并集渲染菜单树与按钮显隐 |

## 二、配置表 `FabViewerRole`

| 字段 | 说明 |
|---|---|
| `id` | 技术主键（底层框架生成，业务侧不感知，**接口不用它定位**） |
| `roleId` | **角色标识 —— 唯一索引**（`varchar2(50)`；创建后锁定，编辑不可改） |
| `roleName` | 角色名称（必填，展示用） |
| `description` | 描述（纯文本，长度 ≤ 4000，多行文本域） |
| `permissions` | **行内 JSON**：字符串数组，元素 = 前端注册的**功能菜单路径**与**按钮路径**（见 §三） |
| `enabled` | 停用 = 该角色不参与权限合并（用户视同未挂它） |
| `updatedAt` / `updatedBy` | 审计 |

**内置角色 `ADMIN`**：种子初始化；**不可删除**（**前端控制**，后端不校验）、不可停用；permissions 恒为全量（编辑时可看不可改，视觉细节归原型）。

## 三、权限模型（路径由前端组织）

### 3.1 两级权限对象

| 级 | 对象 | 说明 |
|---|---|---|
| 菜单权限 | **功能菜单**（实际可打开的功能页） | 权限**只管到功能菜单**这一层；**上级菜单目录不是权限对象** —— 但可**按上级目录统一设定**（勾目录 = 批量勾选其下全部功能菜单，操作便利，归前端树控件联动） |
| 按钮权限 | 功能菜单内的**按钮** | **依附于菜单权限**：只有拥有该菜单权限才可拥有其按钮权限；**按钮权限根据菜单权限变化** —— 取消某菜单 ⇒ 其下按钮权限一并失效并移除 |

### 3.2 存储形态

| 项 | 口径 |
|---|---|
| 注册表 | 前端代码内置**全量**菜单树（目录 → 功能菜单 → 按钮）与路径命名，随版本演进 —— **无后端接口** |
| 路径形态 | 功能菜单：`<模块>.<页面>`（如 `module1.ruleInfo`）；按钮：`<模块>.<页面>.btn.<动作>`（如 `module1.ruleInfo.btn.export`）—— 具体命名由前端注册表定，本文只定结构 |
| 存什么 | **只存功能菜单路径与按钮路径**（目录不存）；扁平字符串数组混放，前端自行识别层级 |
| 合法性约束 | 集合内任一按钮路径，其所属菜单路径**必须同时在集合内**（由**前端**保证并拦截；**后端不校验，原样存取**） |
| 下发 | 登录后随 `auth/me` 一次性下发并集（`03` §五-1）；前端全局过滤 |

## 四、页面逻辑

| 项 | 口径 |
|---|---|
| 进入页面 | 调 `page` 取第一页（每页 20，不分档） |
| 列（按序） | Role ID、Role Name、Description、Enabled、Last Updated Time、Last Updated User + Action（编辑 / 删除） |
| 添加 / 编辑 | 弹框表单：Role ID（编辑时锁定）、Role Name、Description、**权限树**（渲染前端注册表：目录可批量勾、功能菜单逐个勾、按钮在菜单勾选后才可勾；取消菜单自动清其按钮） |
| 删除 | 弹框确认；**角色被用户挂载中 ⇒ 不允许删除**（提示挂载数，先在用户管理摘除）；`ADMIN` 不可删由**前端控制**（后端不校验） |
| 保存 | 权限变更**不即时踢人** —— 已登录会话在下次拉取权限（重新登录 / 前端刷新权限）时生效 |

## 五、接口清单

外壳一律走**统一响应包**。

| # | 接口 | Method | 用途 |
|---|---|---|---|
| 1 | `security-management/api/v1/role/page` | `GET` | 角色分页（含 `permissions`） |
| 2 | `security-management/api/v1/role` | `POST` | 新增（`roleId` 冲突即拒） |
| 3 | `security-management/api/v1/role` | `PUT` | 编辑（`roleId` 定位；`roleId` 不可改，传原值或忽略） |
| 4 | `security-management/api/v1/role` | `DELETE` | 删除（入参 `roleId`；`ADMIN` 由前端控制不可删；被用户挂载中的处置待定） |
| 5 | `security-management/api/v1/role/list` | `GET` | 全量启用角色候选（用户管理挂角色用；不分页） |

- POST / PUT 入参：`{ roleId, roleName, description, permissions: [ …路径 ] }`（`roleId` 定位角色）。
- `permissions` **后端不校验**，原样存取；内容合法性（含按钮依附菜单）全部由前端保证（§3.2）。

## 六、待定

- `ADMIN` 的 permissions 存「全量路径数组」还是「哨兵值 `["*"]`」—— **归前端决定，后端不涉及**（后端只管存，见 §3.2）。
- 删除前「被挂载数」的提示取数（删除接口报错带回，或独立查询——后端定）。
