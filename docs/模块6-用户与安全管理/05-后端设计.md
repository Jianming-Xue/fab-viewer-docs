## 一、全局约定

### 1.1 技术底座

| 项 | 口径 |
|---|---|
| 数据库 | **Oracle 11g** |
| 后端语言 | **Go** |
| 技术主键 | 由底层框架生成，业务侧不感知，接口不用它定位 |
| 审计字段 | `updatedAt` / `updatedBy` 等由底层统一处理，不列入业务字段 |
| 布尔字段 | Oracle 无 `BOOLEAN`，落库一律 `Number(1)`：**`0` = false 停用，`1` = true 启用**，Go 侧 `bool` ↔ 0/1 映射 |

### 1.2 Oracle 11g 硬约束

1. **没有 `IS JSON` 约束**（12.1.0.2 起才提供）—— 存 JSON 的列，合法性只能由服务端保证，库层兜不了。
2. **`VARCHAR2(n)` 默认字节语义**（`BYTE`）—— AL32UTF8 下一个汉字占 3 字节，长度按**字节**校验，超出直接报错而非截断。

### 1.3 请求分页 `PageRequest`（底层提供）

| 字段 | 类型 | 说明 |
|---|---|---|
| `pageIndex` | int | 页码 |
| `pageSize` | int | 每页条数 |

### 1.4 全局响应包

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 成功**恒 `OK`**；失败为自定义业务码 |
| `success` | bool | 内部为布尔，**输出前转成 `0` / `1`** |
| `errMsg` | string | 失败原因；成功为空串 |
| `data` | object | 业务数据；分页接口为 `Pageable`（§1.5） |
| `txId` | string | 读请求 Header 的 `txId`，**原样返回**；无则空串 |

- **HTTP 状态码**：业务类失败（参数错、无权限、业务规则拒绝）**恒 200**，成败只看 `success`；仅服务端内部错误（panic、DB 不可用等）返回 5xx，且不出本响应包。

### 1.5 分页出参 `Pageable`

| 字段 | 类型 | 说明 |
|---|---|---|
| `pageIndex` | int | 当前页码（与入参一致） |
| `pageSize` | int | 每页条数 |
| `totalSize` | int | 总条数 |
| `totalPage` | int | 总页数 |
| `data` | array | 当前页数据 |

```json
{
  "code": "OK",
  "success": 1,
  "errMsg": "",
  "data": {
    "pageIndex": 1,
    "pageSize": 20,
    "totalSize": 12,
    "totalPage": 1,
    "data": []
  },
  "txId": "3f9c1b7e2a4d"
}
```

### 1.6 命名约定

| 层 / 用途 | 后缀 | 示例 |
|---|---|---|
| API 请求入参对象 | `Ro` | `RoleRo`、`AssignRolePermissionRo` |
| API 出参对象 | `Dto` | `RoleDto`、`RoleNameDto` |

### 1.7 URL 规则

服务内路径形如 **`/api/v1/<资源前缀>/…`**；对外完整路径由 nginx 在最前加服务名：`security-management/api/v1/…`（nginx 按路径第一段分发到本服务）。**本文只写服务内前缀。**

各资源前缀（按需求方给定名称，不统一单复数风格）：

| 资源 | 服务内前缀 |
|---|---|
| 角色 | `/api/v1/roles`（复数） |

## 二、数据模型

### 2.1 表 `FabViewerRole`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `roleId` | `varchar2(50)` | **唯一索引** | 角色标识 —— 业务唯一键，与底层技术主键无关；接口一律用 `roleId` 定位 |
| `roleName` | `varchar2(63)` | **NOT NULL** | 角色名称 |
| `description` | `varchar2(255)` | — | 描述 |
| `enabled` | `Number(1)` | 默认 `0` | 启用 / 停用（`0` = 停用，`1` = 启用） |
| `permissions` | `CLOB` | — | 权限集合，存 JSON 数组字符串 |

### 2.2 字段口径

| 字段 | 口径 |
|---|---|
| `roleId` | 唯一；**创建后锁定，编辑不可改**；长度按 50 字节校验（中文按 3 字节计，约 16 个汉字） |
| `roleName` | 必填；长度按 63 字节校验（约 21 个汉字） |
| `description` | 可空；长度按 255 字节校验（约 85 个汉字） |
| `enabled` | 新建默认 `false`；停用不删用户挂载关系，权限合并时跳过该角色 |
| `permissions` | **存什么由前端决定，后端只管存**：原样写入、原样读出；不校验 JSON 合法性、不校验路径是否存在、不校验按钮与菜单的依附关系 |

### 2.3 落库形态

| 场景 | 落库值 |
|---|---|
| 新建角色 | `enabled = 0`；`permissions = "[]"`（**空 JSON 数组的字符串，不是 `NULL`**） |
| 配置权限 | 集合序列化成 JSON 数组字符串，**整集合覆盖**，不做增量合并 |
| 出参还原 | `permissions` 由 JSON 字符串解析成字符串集合返回 |

## 三、接口

### 3.1 接口总表

| # | 方法 | 路径 | 传参 | 出参 | 用途 |
|---|---|---|---|---|---|
| 1 | `GET` | `/api/v1/roles/page` | query：`pageIndex`、`pageSize`、`keyword` | `Pageable`（元素 `RoleDto`） | 角色分页 |
| 2 | `POST` | `/api/v1/roles` | body：`RoleRo` | `RoleDto` | 新建角色 |
| 3 | `PUT` | `/api/v1/roles` | body：`RoleRo` | `RoleDto` | 修改角色 |
| 4 | `DELETE` | `/api/v1/roles` | query：`roleId` | 空 | 删除角色 |
| 5 | `POST` | `/api/v1/roles/permissions` | body：`AssignRolePermissionRo` | `RoleDto` | 配置权限 |
| 6 | `POST` | `/api/v1/roles/enabled` | query：`roleId`、`enabled` | `RoleDto` | 启用 / 停用 |
| 7 | `GET` | `/api/v1/roles/name/list` | 无 | `RoleNameDto` 数组 | 启用角色名称列表 |

### 3.2 角色分页 `GET /api/v1/roles/page`

**入参**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pageIndex` | int | 是 | 分页参数（§1.3） |
| `pageSize` | int | 是 | 分页参数（§1.3） |
| `keyword` | string | 否 | 非空时对 `roleId` / `roleName` / `description` 三列**同时模糊匹配（OR）**；为空不加条件，分页返回全部 |

**出参**：`data` = `Pageable`（§1.5），`data.data` 元素为 `RoleDto`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `roleId` | string | 角色标识 |
| `roleName` | string | 角色名称 |
| `description` | string | 描述 |
| `enabled` | number | `0` = 停用，`1` = 启用 |
| `permissions` | string 集合 | 权限路径数组 |

**匹配规则**

| 项 | 口径 |
|---|---|
| 匹配列 | `roleId`、`roleName`、`description` 三列，任一命中即返回 |
| `description` 为空 | 该列不命中，不影响其他两列 |
| 空 `keyword` | `trim` 后为空即视为未传，不拼条件 |
| 大小写 | **统一转全大写后匹配**：`keyword` 与三列都经 `UPPER()` 再 `LIKE`（`admin` 能搜到 `ADMIN`） |

**排序**：`roleId` 升序。

### 3.3 新建角色 `POST /api/v1/roles`

**入参 `RoleRo`**（新建与修改共用）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `roleId` | string | 是 | 角色标识；唯一，创建后不可改 |
| `roleName` | string | 是 | 角色名称 |
| `description` | string | 否 | 描述 |

> 入参**不含** `enabled` 与 `permissions`：新建时 `enabled` 落 `0`，`permissions` 落 `"[]"`（§2.3）。

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | app 层校验：`roleId`、`roleName` 不能为空（`trim` 后判空） |
| 2 | 按 `roleId` 查 `FabViewerRole` |
| 3 | 已存在 → 抛业务异常（`roleId` 重复） |
| 4 | 不存在 → 调 TXN 直接保存 |
| 5 | 保存成功 → 取返回的 `RoleEntity`，打包成 `RoleDto` 返回 |

**出参 `RoleDto`**：`roleId` / `roleName` / `description`（string）、`enabled`（number）、`permissions`（string 集合）。

### 3.4 修改角色 `PUT /api/v1/roles`

**入参**：同 `RoleRo`，`roleId` 只作定位键，**不参与修改**。

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | app 层校验：`roleId`、`roleName` 不能为空（`trim` 后判空） |
| 2 | 按 `roleId` 查是否已存在 |
| 3 | 不存在 → 抛业务异常（角色不存在） |
| 4 | 已存在 → 调 **Modify Attribute 的 TXN**，只修改 `roleName` 与 `description` |
| 5 | 成功 → 取返回的 `RoleEntity`，打包成 `RoleDto` 返回 |

- `enabled`、`permissions` 本接口不改。

### 3.5 删除角色 `DELETE /api/v1/roles?roleId=xxx`

**入参**：query 参数 `roleId`。

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 按 `roleId` 查角色是否已创建 |
| 2 | 未创建 → 抛业务异常（角色不存在） |
| 3 | 已创建 → 校验「是否被用户使用」（**待定**，见 §7） |
| 4 | 确认通过 → 调删除 TXN 删除 |

**出参**：`data` 为空。

### 3.6 配置权限 `POST /api/v1/roles/permissions`

**入参 `AssignRolePermissionRo`**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `roleId` | string | 是 | 角色标识，定位用 |
| `permissions` | string 集合 | 是 | 权限路径集合，原样存入 |

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 校验 `roleId` 不能为空（`trim` 后判空） |
| 2 | 按 `roleId` 查角色是否已创建 |
| 3 | 未创建 → 抛业务异常（角色不存在） |
| 4 | 已创建 → 调 **Modify Attribute 的 TXN**，只更新 `permissions` |
| 5 | 集合序列化成 JSON 数组字符串写入 CLOB，**整集合覆盖** |

**出参**：`RoleDto`（含刚写入的 `permissions`）。

### 3.7 启用 / 停用 `POST /api/v1/roles/enabled?roleId=xxx&enabled=1`

**入参**：query 参数，**直接作为方法参数传入，不建 Ro 对象**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `roleId` | string | 是 | 角色标识，定位用 |
| `enabled` | number | 是 | `1` = 启用（true），`0` = 停用（false） |

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 校验 `roleId` 不能为空（`trim` 后判空） |
| 2 | 按 `roleId` 查角色是否已创建 |
| 3 | 未创建 → 抛业务异常（角色不存在） |
| 4 | 已创建 → 调 **Modify Attribute 的 TXN**，只更新 `enabled` |

**出参**：`RoleDto`。

### 3.8 角色名称列表 `GET /api/v1/roles/name/list`

**入参**：无。

**逻辑**：一条 SQL 取 `enabled = 1` 的角色，返回 `roleId` + `roleName`，不分页。

**出参**：`RoleNameDto` 数组

| 字段 | 类型 | 说明 |
|---|---|---|
| `roleId` | string | 角色标识 |
| `roleName` | string | 角色名称 |

- 只回启用角色。
- 排序：`roleId` 升序。

## 四、策略

### 4.1 数据模型

#### 4.1.1 表 `FabViewerPolicy`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `policyId` | `varchar2(50)` | 唯一索引 | 策略标识 |
| `policyName` | `varchar2(63)` | NOT NULL | 策略名称 |
| `description` | `varchar2(255)` | — | 描述 |
| `passwdMinLength` | `Number(3)` | — | 密码最小长度 |
| `passwdMaxLength` | `Number(3)` | — | 密码最大长度 |
| `passwdRequireDigit` | `Number(1)` | — | 至少一个数字（`0` / `1`） |
| `passwdRequireLowerChar` | `Number(1)` | — | 至少一个小写字母（`0` / `1`） |
| `passwdRequireUpperChar` | `Number(1)` | — | 至少一个大写字母（`0` / `1`） |
| `passwdRequireSpecialChar` | `Number(1)` | — | 至少一个特殊字符（`0` / `1`） |
| `passwdSpecials` | `varchar2(255)` | — | 指定的特殊字符集合 |
| `passwdValidDays` | `Number(6)` | — | 密码有效期天数，**可存 `-1`** |
| `accountValidDays` | `Number(6)` | — | 账户有效期天数，**可存 `-1`** |
| `idleLogoutMinutes` | `Number(6)` | — | 空闲登出分钟数，**可存 `-1`** |

> **本表不设 `isDefault`、不设 `enabled`** —— 策略没有「默认」与「停用」两个状态。`01` 原有的「全表恒有且仅有一条默认策略」「停用的策略视同不存在、挂它的用户回落默认」两条口径**同时作废**（用户未挂策略时的处理见 §4.3）。
>
> `passwdMinLength` / `passwdMaxLength` 为**数字**（长度值），其余 4 个 `passwdRequire*` 为布尔（`Number(1)`）。
>
> **三条补充口径**
>
> | 项 | 口径 |
> |---|---|
> | `policyName` | **不唯一**，只是一个名字；仅要求非空，不做重名校验 |
> | `passwdValidDays` / `accountValidDays` / `idleLogoutMinutes` 的 `-1` | **表示不限制**（密码永不过期 / 账户永不过期 / 不因空闲登出） |
> | `-1` 的生效判定 | **在认证链路（auth）中处理**，本模块只负责存与取，不做折算 |

### 4.2 接口

服务内前缀 **`/api/v1/login_policy`**（§1.7）。**本模块不提供分页接口** —— 全量列表走 `/list`，一次取回。

| # | 方法 | 路径 | 传参 | 出参 | 用途 |
|---|---|---|---|---|---|
| 1 | `GET` | `/api/v1/login_policy/list` | 无 | `PolicyDto` 数组 | 全量列表 |
| 2 | `GET` | `/api/v1/login_policy/name/list` | 无 | `PolicyNameDto` 数组 | 名称列表 |
| 3 | `GET` | `/api/v1/login_policy/detail` | query：`policyId` | `PolicyDto` | 策略详情 |
| 4 | `POST` | `/api/v1/login_policy` | body：`PolicyRo` | `PolicyDto` | 新建策略 |
| 5 | `PUT` | `/api/v1/login_policy` | body：`PolicyRo` | `PolicyDto` | 修改策略 |
| 6 | `DELETE` | `/api/v1/login_policy` | query：`policyId` | 空 | 删除策略 |

> 6 个接口的入参、出参、业务逻辑均已定稿。策略无 `enabled` 字段，故无启停接口。

#### 4.2.1 全量列表 `GET /api/v1/login_policy/list`

**入参**：无。

**逻辑**：一条 SQL 取 `FabViewerPolicy` 全表，不筛选、不分页。

**出参 `data`**：`PolicyDto` 数组，**含表中全部业务字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `policyId` | string | 策略标识 |
| `policyName` | string | 策略名称 |
| `description` | string | 描述 |
| `passwdMinLength` | number | 密码最小长度 |
| `passwdMaxLength` | number | 密码最大长度 |
| `passwdRequireDigit` | number | 至少一个数字（`0` / `1`） |
| `passwdRequireLowerChar` | number | 至少一个小写字母（`0` / `1`） |
| `passwdRequireUpperChar` | number | 至少一个大写字母（`0` / `1`） |
| `passwdRequireSpecialChar` | number | 至少一个特殊字符（`0` / `1`） |
| `passwdSpecials` | string | 指定的特殊字符集合 |
| `passwdValidDays` | number | 密码有效期天数（`-1` 为原值透出） |
| `accountValidDays` | number | 账户有效期天数（`-1` 为原值透出） |
| `idleLogoutMinutes` | number | 空闲登出分钟数（`-1` 为原值透出） |

- 4 个 `passwdRequire*` 出参为 **number（`0` / `1`）**，与 `RoleDto.enabled` 同一形态。
- `passwdValidDays` / `accountValidDays` / `idleLogoutMinutes` 的 `-1` **不折算**，原样返回（`-1` = 不限制，生效判定在认证链路）。
- 排序：`policyId` 升序（**推定**，与角色分页一致）。

#### 4.2.2 策略名称列表 `GET /api/v1/login_policy/name/list`

**入参**：无。

**逻辑**：一条 SQL 只取 `policyId`、`policyName` 两列，不分页。

**出参 `data`**：`PolicyNameDto` 数组

| 字段 | 类型 | 说明 |
|---|---|---|
| `policyId` | string | 策略标识 |
| `policyName` | string | 策略名称 |

- 策略表无 `enabled` 字段，**没有「只取启用项」的过滤**，全表返回（与角色名称列表不同）。
- 排序：`policyId` 升序（**推定**，与 `/list` 一致）。

#### 4.2.3 策略详情 `GET /api/v1/login_policy/detail`

**入参**：query 参数 **`policyId`**（`GET /api/v1/login_policy/detail?policyId=xxx`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `policyId` | string | 是 | 策略标识，定位用 |

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 校验 `policyId` **不能为空**（`trim` 后判空） |
| 2 | 按 `policyId` 查 `FabViewerPolicy` |
| 3 | **未创建** → 抛业务异常（策略不存在） |
| 4 | **已创建** → 组装 `PolicyDto` 返回 |

**出参 `data`**：`PolicyDto`，字段与 §4.2.1 完全一致（13 个业务字段）。

#### 4.2.4 新建策略 `POST /api/v1/login_policy`

**入参 `PolicyRo`**（13 个业务字段全给，`policyId` 由前端录入）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `policyId` | string | 是 | 策略标识；唯一，创建后不可改 |
| `policyName` | string | 是 | 策略名称 |
| `description` | string | 否 | 描述 |
| `passwdMinLength` | number | 是 | 密码最小长度，**≥ 6** |
| `passwdMaxLength` | number | 是 | 密码最大长度，**≥ 18** 且 **> `passwdMinLength`** |
| `passwdRequireDigit` | number | 是 | `0` / `1` |
| `passwdRequireLowerChar` | number | 是 | `0` / `1` |
| `passwdRequireUpperChar` | number | 是 | `0` / `1` |
| `passwdRequireSpecialChar` | number | 是 | `0` / `1` |
| `passwdSpecials` | string | 条件必填 | **`passwdRequireSpecialChar = 1` 时不能为空，且至少含一个字符** |
| `passwdValidDays` | number | 是 | 密码有效期天数，**`-1` 或 `1 ~ 999`** |
| `accountValidDays` | number | 是 | 账户有效期天数，**`-1` 或 `1 ~ 999`** |
| `idleLogoutMinutes` | number | 是 | 空闲登出分钟数，**`-1` 或 `1 ~ 9999`** |

**校验（后端兜底，按序）**

| 序 | 规则 | 拒绝条件 |
|---|---|---|
| 1 | `policyId`、`policyName` 非空 | `trim` 后为空 |
| 2 | `passwdMinLength` 下界 | `< 6` |
| 3 | `passwdMaxLength` 下界 | `< 18` |
| 4 | 长度大小关系 | `passwdMaxLength <= passwdMinLength` |
| 5 | `passwdValidDays` 取值 | 既不是 `-1`，也不在 `1 ~ 999` |
| 6 | `accountValidDays` 取值 | 既不是 `-1`，也不在 `1 ~ 999` |
| 7 | `idleLogoutMinutes` 取值 | 既不是 `-1`，也不在 `1 ~ 9999` |
| 8 | 特殊字符条件必填 | `passwdRequireSpecialChar = 1` 且 `passwdSpecials` 为空（`trim` 后空串） |
| 9 | `policyId` 查重 | 该 `policyId` 已存在 |

> 长度**上限**（`passwdMinLength ≤ 999`、`passwdMaxLength ≤ 999`）不单独校验 —— `Number(3)` 列宽自然兜住，超出由 DB 报错。密码本身**长度区间校验不在后端**（§4.3，前端兜底）。
>
> 4 个 `passwdRequire*` 入参为 `0` / `1`，只判真假，不做其他取值校验。

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 按上表顺序校验，任一不过即抛业务异常 |
| 2 | 调**新建 TXN**保存整条记录（13 个字段全落库） |
| 3 | 取返回的 `PolicyEntity` 打包成 `PolicyDto` 返回 |

**出参 `data`**：`PolicyDto`（新建后整条记录，字段同 §4.2.1）。

#### 4.2.5 修改策略 `PUT /api/v1/login_policy`

**入参**：同 `PolicyRo`（§4.2.4，13 个字段全传）；**`policyId` 只作定位键，不参与修改**。

**校验**：与新建**完全一致**（§4.2.4 校验表的 1 ~ 8 步），仅第 9 步换成「必须已存在」：

| 序 | 规则 | 拒绝条件 |
|---|---|---|
| 9 | `policyId` 存在性 | 该 `policyId` **不存在** |

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 按 §4.2.4 校验表 1 ~ 8 步校验入参 |
| 2 | 按 `policyId` 查策略是否存在 |
| 3 | **不存在** → 抛业务异常（策略不存在） |
| 4 | **已存在** → 调 **Modify Attribute 的 TXN**，更新除 `policyId` 外的 **12 个字段**（`policyId` 仅定位，不落更新） |
| 5 | 成功 → 取返回的 `PolicyEntity` 打包成 `PolicyDto` 返回 |

- 修改是**整表单提交**：12 个字段全部按入参覆盖，不做「只改传了的字段」式局部合并。

**出参 `data`**：`PolicyDto`。

#### 4.2.6 删除策略 `DELETE /api/v1/login_policy`

**入参**：query 参数 **`policyId`**（`DELETE /api/v1/login_policy?policyId=xxx`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `policyId` | string | 是 | 策略标识，定位用 |

**处理流程**

| 步 | 动作 |
|---|---|
| 1 | 校验 `policyId` **不能为空**（`trim` 后判空） |
| 2 | 按 `policyId` 查策略是否已创建 |
| 3 | **未创建** → 抛业务异常（策略不存在） |
| 4 | **已创建** → 校验「是否被用户挂载」—— **本步待定**（见下） |
| 5 | 确认通过 → 调**删除 TXN**删除该策略 |

**待定：是否被用户挂载**

- 判定依据：`FabViewerUser.policyId` 指向该策略即视为「被挂载」。
- 待定的是**判定后的处置**：拒删并提示挂载人数 / 允许删并把挂载用户的 `policyId` 置空 / 其他。本步未定前，删除接口不做该判定。
- 与角色删除接口的「是否被用户使用」是同一类待定项，处置口径宜一并定。

**出参 `data`**：空（与删除角色一致，**推定**）。

### 4.3 校验责任划分

| 规则 | 校验方 | 口径 |
|---|---|---|
| 策略必须挂到用户 | **后端** | 保存用户时 `policyId` **必填**，不接受「不挂策略」 |
| 密码长度区间（`passwdMinLength` ~ `passwdMaxLength`） | **前端** | 用户改密时由前端兜底校验，**后端不重复校验长度** |
| `-1`（不限制）的过期 / 登出判定 | **认证链路 auth** | 本模块只存不折算；密码过期、账户过期、空闲超时的判定放在 auth |

## 五、通用业务规则

### 5.1 校验清单

**角色**

| 校验项 | 适用接口 | 规则 | 不满足 |
|---|---|---|---|
| `roleId` 非空 | 新建 / 修改 / 配置权限 / 启停 | `trim` 后非空 | 参数异常 |
| `roleName` 非空 | 新建 / 修改 | `trim` 后非空 | 参数异常 |
| `roleId` 不可重复 | 新建 | 查无同 `roleId` 记录 | 业务异常：`roleId` 已存在 |
| `roleId` 必须存在 | 修改 / 删除 / 配置权限 / 启停 | 按 `roleId` 查得到记录 | 业务异常：角色不存在 |

**登录策略**（新建与修改共用，详见 §4.2.4）

| 校验项 | 规则 | 不满足 |
|---|---|---|
| `policyId`、`policyName` 非空 | `trim` 后非空 | 参数异常 |
| `passwdMinLength` 下界 | `>= 6` | 参数异常 |
| `passwdMaxLength` 下界 | `>= 18` | 参数异常 |
| 长度大小关系 | `passwdMaxLength > passwdMinLength` | 参数异常 |
| `passwdValidDays` | `-1` 或 `1 ~ 999` | 参数异常 |
| `accountValidDays` | `-1` 或 `1 ~ 999` | 参数异常 |
| `idleLogoutMinutes` | `-1` 或 `1 ~ 9999` | 参数异常 |
| 特殊字符条件必填 | `passwdRequireSpecialChar = 1` 时 `passwdSpecials` 非空 | 参数异常 |
| `policyId` 唯一性 | 新建：查无同 `policyId`；修改：必须存在 | 业务异常：`policyId` 已存在 / 策略不存在 |

### 5.2 写入方式

| 资源 | 接口 | 写入方式 | 更新属性 |
|---|---|---|---|
| 角色 | 新建 | TXN 直接保存 | 全字段插入（`enabled=0`、`permissions="[]"`） |
| 角色 | 修改 | Modify Attribute 的 TXN | 仅 `roleName`、`description` |
| 角色 | 配置权限 | Modify Attribute 的 TXN | 仅 `permissions` |
| 角色 | 启停 | Modify Attribute 的 TXN | 仅 `enabled` |
| 策略 | 新建 | TXN 直接保存 | 13 个字段全插入 |
| 策略 | 修改 | Modify Attribute 的 TXN | 除 `policyId` 外的 12 个字段整体覆盖 |
| 策略 | 删除 | 删除 TXN | — |

- 所有更新接口里，`roleId` / `policyId` 只作定位键，**不参与更新**。

### 5.3 前端管控项（后端不校验）

| 项 | 说明 |
|---|---|
| `ADMIN` 不可删除、不可停用 | 后端不识别 `ADMIN` 字面值，不设特例 |
| `permissions` 内容合法性 | JSON 结构、路径是否存在、按钮是否依附于同集合内的菜单，全部由前端保证 |

## 六、错误场景

| 场景 | 触发接口 | code |
