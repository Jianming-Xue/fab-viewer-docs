# 模块 6 · 用户与安全管理 · 概览

| 项 | 内容 |
|---|---|
| 定位 | 平台的**账号体系与访问控制**：谁能登录（Login Policy）、是谁（用户）、能干什么（角色 → 菜单与按钮权限） |
| 使用者 | IT 运维（管理端）；**全部登录用户**（权限消费方） |
| 状态 | 需求骨架（沟通中） |
| 来源 | Halo「用户管理」（等级 1，性质**重做**）的展开升级 |

> 本模块是**所有页面的前置依赖**：前端菜单树与按钮显隐按本模块下发的权限渲染；登录与改密按本模块的策略校验。

---

## 一、功能清单

| # | 功能 | 一句话 | 文档 |
|---|---|---|---|
| 1 | Login Policy | 登录策略：密码长度 / 字符构成 / 特殊字符集合 / 密码有效期 / 账户有效期（`-1` = 永不过期），用户直挂一条 | `01-Login Policy.md` |
| 2 | 角色管理 | 角色 CRUD（`roleId` 唯一）；行内 JSON 存权限（菜单 / 按钮路径，由前端组织）；**只管功能访问权限** | `02-角色管理.md` |
| 3 | 用户管理 | 用户 CRUD；挂**多个角色**（权限并集）与**一条 Login Policy**；两个到期日折算存档；重置密码 / 自助改密；本地账户、预留 AD | `03-用户管理.md` |
| 4 | Login History | 登录历史：**只写不删**，按账号 / 时间段只读查询 | `04-Login History.md` |

## 二、依赖关系

```
用户 ──挂载（多对多）──→ 角色 ──permissions（行内 JSON）──→ 前端全局：菜单树过滤 + 按钮显隐（多角色取并集）
  │
  └──挂载（一条，可空 = 默认）──→ Login Policy ──→ 登录 / 改密 / 重置 的校验与两个到期日的折算
```

- **角色与策略解耦、都直接挂用户**：角色只管功能访问权限（`02`）；登录策略逐用户挂一条、无合并计算（`01` §2.2）。
- **用户 → 角色**：多对多（一个用户可挂**多个有效角色**）；权限 = 各有效角色 permissions 的**并集**。
- **权限的组织者**：菜单与按钮的**路径注册表由前端内置**（随版本演进）；本模块只存与下发被勾选的路径集合，后端不解析。

## 三、表清单（全项目表规范：`FabViewer` 前缀 + `id` 技术主键 + `enabled` + `updatedAt`/`updatedBy`；`enabled` 缺省者除外）

| 表 | 归属 | 说明 |
|---|---|---|
| `FabViewerLoginPolicy` | 功能 1 | 登录策略（多条，一条为默认；9 项规则，含特殊字符集合） |
| `FabViewerLoginHistory` | 功能 4 | 登录历史（**只写不删**，无 `enabled`、无更新） |
| `FabViewerRole` | 功能 2 | 角色（`roleId` 唯一；`permissions` 行内 JSON；被用户挂载中拒删） |
| `FabViewerUser` | 功能 3 | 用户（`username` 唯一；`policyId` 直挂策略；两个到期日存档；`authType` = LOCAL / AD 预留） |
| `FabViewerUserRole` | 功能 3 | 用户-角色关系（唯一键 `userId`+`roleId`） |

## 四、微服务与认证边界

- **微服务**：本模块的**全部接口**走独立的 **`security-management` 微服务**（与日志主服务 **`log-viewer`** 分立部署）—— 接口路径统一为 `security-management/api/v1/…`（模块 1 / 5 的接口前缀为 `log-viewer/api/v1/…`）：**服务名在最前**，由 **nginx 按路径第一段分发**到对应微服务。
- **本模块管**：账号数据、密码规则、两个到期日判定所需数据、权限集合的下发。
- **认证链路**（登录接口、密码哈希、token / 会话的签发与续期、接口鉴权拦截）实现在 security-management 微服务内，接口契约不在功能文档清单中。
- **AD**：本期仅本地账户；`authType` 预留 `AD`，对接口径后续另定（届时登录走域校验、本地不存密码）。

## 五、与其他模块的边界

| 部分 | 归属 |
|---|---|
| 系统管理类配置（Hang Reason Config、System Misc 等） | 模块 5 |
| 操作审计（谁改了什么配置） | 本期不做（登录历史先行） |
| 数据权限（按环境 / Server 划范围） | 本期不做——权限只到菜单与按钮两级 |
