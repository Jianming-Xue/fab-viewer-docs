# 附录A · 块首行解析方案

> 本文件是 `06-派生服务工程实现.md` §八「块首行参数解析」的**执行细则**，把那一节的口径摊成可直接照抄的步骤与伪代码。
>
> **两端都要实现同一套算法**：派生层（Go，建块时跑）与前端（展示层按块 `id` 拉回首行后复盘时跑）。所以下面是**语言无关伪代码**，不依赖 Go 或 JS 的库。
>
> 样例取自 `04-后台链路与数据模型.md` §7.4：A = 标准 API2、B = XML、C = 自动 Rule、D = TXN（只取 TxnName）。

---

## 〇、适用与产出

**输入**：块首行 `LOG_BODY`（一整行原始日志，含时间戳与服务名前缀）。

**门禁：按 `REQUEST_TYPE` 分流，两条路**（判据见 §八「第一级：类型」）—— `Rule` 块走 **一 ~ 三**（三步）；`TXN` 块走 **四**（一步，只取 TxnName）。两条路都产出同一个 KV 集合，下游取字段不分叉。

**产出**：

1. 一个 **KV 集合** —— Rule 块是「请求头的键 + `attributes` 里的键」合成；`TXN` 块只有一对（`ruleName` = TxnName，见 §四）；
2. 若集合里有 `K = XMLDATA`，再把它的 Value 交 XML 解析器，得到一个 **XML 对象**。

**本期只解析固定键**：**「不收入」指不收入块文档，不是不收入 KV 集合** —— 切块照切，**动态键条目（键本身是业务对象 ID）照常留在 KV 集合里**，只是**不落进块文档的字段**。
**参与取值**（即落进七个业务字段）的，**只有键名可归一到标准字段（别名表，见 `04` §7.3）的固定键条目**。取值方式不变：**按配置表查固定键，查到就取、查不到才留空**。

> 由此，**产出 1 的 KV 集合是「全集」** —— 固定键与动态键条目都在里面；「只解析固定键」限制的是**写进块文档的那几步**，不是集合本身。前端复盘时拿到的是同一个全集。

**七个业务字段的取法只有一条：在解析出来的 KV 集合里按字段配置表（`04` §7.3）查** —— 键名归一化后落标准字段，取到就写、取不到留空。

**贯穿全程的一条**：字符扫描时挂两个状态位 —— 引号开合（`"` 翻转）与转义（`\` 跳过下一字符）。**引号内的 `{`、`}`、空格、`=` 一律当字面量，不参与任何结构判断。**

## 一、第一步：剥壳，并切出 `attributes` 段

### 做什么

1. **砍前缀**。从行首一路砍到 `FwEventManager:message to process: :>>L ` **末尾**（含尾随空格）—— 时间戳 `08/11/26 17:19:49.38` 与服务名 `FABsrv.10:` 一并砍掉。
2. **砍方法名**。剩下串里**第一个空格之前**的那个 token 是方法名（Rule 三条样例都是 `FwSrvExecuteRuleTxn`），砍掉。
3. **定位 `attributes={`**。找字面量，记下其中那个 `{` 的位置。
4. **计数找结尾**。从那个 `{` 起扫：`{` 加 1、`}` 减 1，**引号内不计数**。计数**归 0** 的那个 `}` 就是 `attributes` 的结束位置。
5. **摘段**。把 `attributes={ … }` 整段从串里摘掉，**剩下的就是请求头**。

### 兜底

`attributes={` **找不到**，或扫到串尾**计数没归 0** —— 两者都说明这条日志的结构不完整（MES 侧输出有问题），**整条不解析**：七个业务字段整体留空，不做截断，也不打 MISS 标记。

### 伪代码

```text
function step1(body):
    # 1.1 砍前缀字面量（含尾随空格）
    TAG = "FwEventManager:message to process: :>>L "
    p = indexOf(body, TAG)
    if p < 0: return FAIL                 # 不是 Rule 首行
    s = body[p + len(TAG) : ]

    # 1.2 砍方法名：剩下串里第一个空格之前的 token
    q = indexOf(s, " ")
    if q < 0: return FAIL
    s = s[q + 1 : ]

    # 1.3 定位 attributes={ 里那个 {
    a = indexOf(s, "attributes={")
    if a < 0: return FAIL                 # 兜底①：找不到 ⇒ 整条不解析
    braceStart = a + len("attributes=")

    # 1.4 从 { 起计数，直到归 0
    depth = 0
    inQuote = false
    esc = false
    braceEnd = -1
    for i from braceStart to len(s) - 1:
        c = s[i]
        if esc:            esc = false;      continue
        if c == '\\':      esc = true;       continue
        if c == '"':       inQuote = !inQuote; continue
        if inQuote:        continue
        if c == '{':
            depth += 1
        else if c == '}':
            depth -= 1
            if depth == 0: braceEnd = i; break
    if braceEnd < 0: return FAIL          # 兜底②：不归 0 ⇒ 整条不解析

    # 1.5 摘掉 attributes 整段，剩下的是请求头
    attrsData = s[braceStart : braceEnd + 1]      # 含最外层 { }
    header    = trim(s[0 : a] + s[braceEnd + 1 : ])
    return { header, attrsData }
```

### 样例 A 实测

| 项 | 值 |
|---|---|
| 剥壳后串长 | 868 |
| `attributes` 的 `{` 偏移 | 78 |
| 归 0 的 `}` 偏移 | 867（正好在串尾） |
| 摘段后剩下的请求头 | `msgTag=_INBOX.0A14232E.5C00D2590D367AF20D.1 ruleName=AMAJPJIJORULE` |

## 二、第二步：把两段都切成 KV，合成一个集合

### 2.1 请求头：等号定位法

**做法**：先扫出串里**所有 `=` 的位置**，再逐个取键值：

- **Key** —— 从该 `=` **往前回退到第一个空格**，空格与 `=` 之间那段（不含空格）就是 Key。**第一个 `=` 的 Key 起点为 0**（它前面没有空格）。
- **Value** —— 从该 `=` **之后**，到**下一个 `=` 的 Key 起点**为止，去首尾空格。**最后一个 `=` 的 Value 到串尾**，同样去首尾空格。
- 取到的 Key / Value 各**剥掉首尾一对引号**。

**为什么这样切**：它只用空格**回退 Key 的起点**，不用空格去切 Value —— 所以 Value 里含空格（`ruleName="EAPReqJobInEx"`、`subjectName=""`、`systemLevelObjects={ }`）都不会切坏。

**前提**：`=` 紧贴 Key（写成 `key=value`）。若出现 `key = value`（等号前留空格），该 `=` 的 Key 会取到空串 —— 属畸形输入，跳过即可。

### 2.2 `attributes` 内部：切块

`attrsData` 就是 `{ … }` 整段（含最外层花括号）。**先算「内部」** = 去掉 `attributes={` 这个前缀与**最外层那个 `}`**，即 `attrsData[1 : -1]`。

**再切块**：对内部串跑**同一套**计数法 + 引号反转，**每次计数归 0 就把「开始点到结束点」整段收进集合** —— 注意**每块带自己的左右大括号**。

### 2.3 单块取 Key / Value

先剥掉**块自己的**外层 `{ }` 与首尾空格，然后按块的开头分两种：

**（甲）不以 `class=ASSOC` 开头的块** —— 按**第一个空格**切一次，左边 Key、右边 Value，各自剥首尾引号。

> 「第一个空格」不是「所有空格」。`{ "COMMENT" "Skip Dummy for WipControl" }` 的值里有 3 个空格，按所有空格切会把 Value 截成 `"Skip`。样例 A 里有 3 条这样的值（第 7、10、13 块）。

**（乙）以 `class=ASSOC` 开头的块** —— 这一块是**形态声明**，取值走另一条路：

1. 去掉开头的 `class=ASSOC` 与首尾空格；
2. 对剩下的串再跑一遍切块（同 2.2）—— **必须恰好切成 2 块**，第 1 块为 Key、第 2 块为 Value；
3. 每块**内部**（剥自己的 `{ }` 与首尾空格）按**第一个空格**分两段，**取第二段**，剥首尾引号 —— 得到该块的值；
4. **切出来不是 2 块** ⇒ **整条不解析**（同一个兜底）。

> 顺带一句：`class=ASSOC` 这个裸 token 不在花括号里，切块时天然收不到、会被丢掉 —— 形态判据不靠它，靠那 2 块的取值。

### 2.4 合并

请求头 KV + `attributes` 里每块解出的 KV，**放进同一个集合**。`class=ASSOC` 那一块解出的那一对（`PARAMETER` = `VALUE` 等）也进集合。

### 伪代码

```text
# ---- 2.1 请求头：等号定位法 ----
function step2a_header(header):
    eqs = allIndexOf(header, '=')
    out = []
    for n from 0 to len(eqs) - 1:
        p = eqs[n]
        # Key：从 = 往前回退到第一个空格；第一个 = 的起点为 0
        j = lastIndexOf(header, ' ', 0, p)
        keyStart = (j < 0) ? 0 : j + 1
        key = trimQuotes(header[keyStart : p])
        # Value：到下一个 = 的 Key 起点；最后一个到串尾
        if n + 1 < len(eqs):
            j2 = lastIndexOf(header, ' ', 0, eqs[n + 1])
            valEnd = (j2 < 0) ? 0 : j2 + 1
        else:
            valEnd = len(header)
        val = trimQuotes(strip(header[p + 1 : valEnd]))
        out.push({ key, val })
    return out

# ---- 2.2 内部切块（归 0 收一段，带左右大括号）----
function cutBlocks(text):
    blocks = []
    depth = 0; start = -1; inQuote = false; esc = false
    for i from 0 to len(text) - 1:
        c = text[i]
        if esc:            esc = false;       continue
        if c == '\\':      esc = true;        continue
        if c == '"':       inQuote = !inQuote; continue
        if inQuote:        continue
        if c == '{':
            if depth == 0: start = i
            depth += 1
        else if c == '}':
            depth -= 1
            if depth == 0: blocks.push(text[start : i + 1])   # 带 { }
    return blocks

# ---- 2.3 单块取 Key / Value ----
function blockKV(block):
    body = strip(block[1 : -1])                        # 剥块自己的 { } + 首尾空格

    if startsWith(body, "class=ASSOC"):                # （乙）形态声明块
        rest = strip(body[len("class=ASSOC") : ])      # 去掉 class=ASSOC + 首尾空格
        sub  = cutBlocks(rest)
        if len(sub) != 2: return FAIL                  # 兜底③：不是 2 块 ⇒ 整条不解析
        return { key: tailValue(sub[0]),               # 第 1 块为 Key
                 val: tailValue(sub[1]),               # 第 2 块为 Value
                 isForm: true }

    # （甲）普通键值块：按第一个空格切一次
    k, v = partitionAtFirstSpace(body)
    return { key: trimQuotes(k), val: trimQuotes(v), isForm: false }

# 取「块内部」的第二段
function tailValue(piece):
    t = strip(piece[1 : -1])                           # 剥自己的 { } + 首尾空格
    k, v = partitionAtFirstSpace(t)
    return trimQuotes(v)

# ---- 通用小函数 ----
function trimQuotes(s):                                # 只剥首尾一对引号
    s = strip(s)
    if len(s) >= 2 and s[0] == '"' and s[-1] == '"': return s[1 : -1]
    return s

function partitionAtFirstSpace(s):                     # 按第一个空格切一次
    i = indexOf(s, " ")
    if i < 0: return { s, "" }
    return { s[0 : i], strip(s[i + 1 : ]) }

# ---- 2.4 合成 ----
function step2(header, attrsData):
    kvSet = step2a_header(header)
    if attrsData == null: return kvSet
    inner  = attrsData[1 : -1]                         # 去掉 attributes={ 与最外层 }
    for each block in cutBlocks(inner):
        kv = blockKV(block)
        if kv == FAIL: return FAIL                     # 兜底③冒泡上来
        kvSet.push(kv)
    return kvSet
```

### 引号的处理口径

- **只剥首尾那一对**，值内部的引号**一律不动**（样例 B 的 XML 里有一堆 `applicationName="EAP"`，都原样保留）。
- 被转义的引号 `\"` **保留引号、去掉反斜杠**，即存成 `"`。

## 三、第三步：`XMLDATA` 转 XML 对象

### 做什么

在合成好的 KV 集合里找 **`K = XMLDATA`** 的那一对。**只有 XML 形态才有这一对** —— 它的 Value 必然是一整段 XML message（样例 B 是 `<msg>…</msg>`）。把这段字符串**直接交给标准 XML 解析器**，得到一个 XML 对象。

### 取字段口径

- 标签名即 Key，**不做二次解析**；键名是**小驼峰**（`lotId` / `eqpId` / `carrierId` / `portNo` / `userId` / `txId`），归一化后直接比标准字段。
- **位置**：`<txId>` 在 `<msgHeader>` 下，其余在 `<msgBody>` 下。
- **重复出现的兄弟节点整组不取** —— `<slotInfo>` 这类节点出现多次时，组内不取任何标准字段、也不落任何字段。这条同时解决了「同名节点多处」的问题：`<lotId>` 在 `<lotInfo>` 里 1 处、在 24 条 `<slotInfo>` 里各 1 处，**后一组整组不取**，剩下的那处就是答案。

### 伪代码

```text
function step3(kvSet):
    xmlText = null
    for each { key, val } in kvSet:
        if key == "XMLDATA": xmlText = val; break
    if xmlText == null: return null          # 非 XML 形态，走 KV 集合取字段

    node = parseXML(xmlText)                 # 交标准 XML 解析器
    if node == null: return null             # 解析失败 ⇒ 留空

    # 取字段：先按「重复兄弟节点整组不取」剔掉多值组，再按层级取
    return node
```

## 四、TXN 首行：只取 TxnName

**这是与 一 ~ 三并列的另一条路，不是第四步。** 类型在门禁处就分流：`Rule` 走 一 ~ 三；**`TXN` 只走本节，一步到底**。

### 做什么

TXN 首行的请求体是 Tcl 序列化对象（`键 <类型> <值>`，如 `subjectName A1 "XsiteWorkOrder"`），**没有 `attributes=`、也没有 `class=ASSOC`** —— 套不上 Rule 那套 KV 解析。但**请求体的第一个 token 就是 TxnName**，只取它即可：

1. **砍前缀**。从行首一路砍到 `FwEventManager:message to process: :>>T` 之前那些（时间戳、服务名与这段字面量本身）—— 与 Rule 同一个剥壳动作，只把标志换成 `:>>T`。
2. **取 TxnName**。剩下串里**第一个空格之前**的那一段就是 TxnName（样例 D 是 `FwFetchWhereTxn`）。
3. **放进集合**。以 `K = ruleName`、`V = TxnName` 放进 KV 集合 —— **键名与 Rule 请求头里的键完全一致**，下游「查配置表取字段」的代码不用为 TXN 分叉（配置表里 `ruleName` → `RULENAME`，见 `04` §7.3）。

**结果：TXN 块只有 `RULENAME` 取得到**（值为 TxnName）。其余六个字段（`LOTID` / `EQPID` / `PORTID` / `CARRIERID` / `USERID` / `TID`）在 TXN 首行里无从取起，按「取不到就留空」一律留空。

### 兜底

`FwEventManager:message to process: :>>T` **找不到**，或砍完后**取不到 token**（空串）—— `RULENAME` 留空。块照建、`REQUEST_TYPE = TXN` 不受影响。

### 伪代码

```text
function stepTxn(body):
    # 4.1 砍前缀：与 Rule 同一个动作，标志换成 :>>T
    TAG = "FwEventManager:message to process: :>>T"
    p = indexOf(body, TAG)
    if p < 0: return FAIL                 # 不是 TXN 首行
    s = strip(body[p + len(TAG) : ])      # 去掉 :>>T 后的那个空格

    # 4.2 取 TxnName：剩余串里第一个空格之前的那一段
    q = indexOf(s, " ")
    txnName = (q < 0) ? s : s[0 : q]
    if txnName == "": return FAIL         # 兜底：取不到 ⇒ RULENAME 留空

    # 4.3 放进 KV 集合，键名与 Rule 请求头一致
    return [ { key: "ruleName", val: txnName } ]
```

### 样例 D 实测

砍到 `:>>T` 之后的剩余串（原样）：

```text
 FwFetchWhereTxn @0 { subjectName A1 "XsiteWorkOrder" msgTag A1 "" sendAck B1 FALSE … }
```

| 项 | 值 |
|---|---|
| 砍到 `:>>T` 之后的剩余 | 578 字符（`strip` 后 577） |
| 第一个空格之前 | `FwFetchWhereTxn` ⇒ **TxnName** |
| 落进 KV 集合 | `ruleName` = `FwFetchWhereTxn` |
| 取到的字段 | `RULENAME` = `FwFetchWhereTxn`；其余六个留空 |

> **两种剥壳写法等价。** 砍到 `:>>T`（不含尾随空格）再 `strip`，或砍到 `:>>T `（含尾随空格）—— 样例 D 实测两条都得 `FwFetchWhereTxn`。选哪个都行，**但派生层与前端要一致**。

## 六、兜底与边界

| # | 情形 | 处理 |
|---|---|---|
| 1 | `attributes={` 找不到 | **整条不解析**，七字段留空 |
| 2 | 扫到串尾计数**没归 0** | 同上（结构不完整，属 MES 侧输出问题） |
| 3 | `class=ASSOC` 块**切出来不是 2 块** | 同上 |
| 4 | `=` 前不紧贴 Key（`key = value`） | 该 `=` 取到空 Key ⇒ 跳过该对 |
| 5 | 块内只有一个 token（无空格） | 取不到 Value ⇒ 值留空 |
| 6 | 值本身是一串 `K=V`（动态键条目） | 本方案只切到「Key = 那串」；该条目**留在 KV 集合里**，只是**不落进块文档**（不参与七个业务字段的取值，见 §〇） |
| 7 | XML 解析失败 | 留空 |
| 8 | `TXN` 首行取不到 TxnName（前缀缺失 / 无空格） | `RULENAME` 留空（其余六个字段本来就留空，见 §四 兜底） |

**统一语义**：解析不到就**留空，不做 MISS 标记** —— 不是每次请求都带全七个字段，缺失是常态。**一律不截断**：截断会产出「半真半假」的值，比空值更难查。

## 七、两端实现的注意点

1. **纯字符串扫描，不需要正则**。整趟是几遍顺序扫描，没有回溯风险；样例 B 那种 1780 字符的 XML 串也不构成性能问题。
2. **别用「按空格全切」的便捷函数**。请求头按**第一个**空格切（等号定位法），块内也按**第一个**空格切 —— 用 `split(" ")` 取前两段会把含空格的值截断。
3. **两个状态位各自独立**（`inQuote` 与 `esc`），逐字符推进；转义只影响下一个字符。
4. **顺序不能反**：请求头「先切段、再各剥首尾引号」—— 先在整段上去引号会把结构切坏（`"COMMENT" "Skip Dummy for WipControl"` 去引号后分不清哪段是 Key）。
5. **前端照本方案自己实现一遍，不复用派生层的解析产物**。前端是既定接口（`rule_info/detail` 等拉回块首行）之后的复盘实现，派生层是写入实现 —— 同一条首行在两端解出的 KV 集合**必须逐字节一致**，否则展示与存储会对不上。
