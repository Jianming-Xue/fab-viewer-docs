## 一、功能定位

| 项 | 内容 |
|---|---|
| 干什么 | 把**两条 Rule Info 日志**摆在一起比 —— 一条效率高的、一条效率低的，找出差异 |
| 页面布局 | 自上而下三段：**上＝Source 区**、**中＝Target 区**、**下＝对比区** |
| 角色 | **Source = 不好的那条**（被分析的问题样本）；**Target = 好的那条**（对照基准）。两个区进页面即分好角色，界面上带角色标记 |
| 两条怎么来 | **都在本页面各自检索** —— 两个区各有一套条件与 `Search` |

## 二、Source 区（不好的那条）

### 2.1 检索条件

本区共 **5 个条件**：

| # | 控件 | 必填 | 取值来源 | 过滤块文档字段 | 匹配方式 | 不填 / 不选 |
|---|---|---|---|---|---|---|
| 1 | Environment | **是** | 进页面调 `GET log-viewer/api/v1/env/list` | `ENV` | 等值 | 进页面**默认不选中**；为空则不能 `Search` |
| 2 | 开始时间 | **是** | 时间选择器，精确到分钟 | `START_TIME` | 区间下界 | — |
| 3 | 结束时间 | **是** | 时间选择器，精确到分钟 | `START_TIME` | 区间上界 | — |
| 4 | Rule Name | 否 | 手输 | `RULENAME` | **精确匹配**，不支持模糊 | 不过滤 |
| 5 | TID | **是** | 手输，单项值 | `TID` | **精确匹配**，不支持模糊 | — |

**「不支持模糊」的含义**：`*` 按**普通字符**处理 —— 既不做前缀匹配，也**不判非法**（同 `01` 里 `TID` 的处理）。填 `ABC` 就找值恰好是 `ABC` 的块。

**时间细则**：照 `01` §2.2 —— 过滤 `开始时间 ≤ START_TIME ≤ 结束时间`（闭区间）；`开始 ≤ 结束` 且两者差 **≤ 1 天**；清空一端自动补另一端。**默认值**：结束 = 当前时刻、开始 = 当前时刻 − 1 小时（同 `01`）。

**本区不含**：功能 1 的其余条件（Host IP、Server Category / Number、EQP、Carrier、Lot、Min / Max Cost Time、折叠区 4 项、`Desc Time` 开关）本功能一概不设。

### 2.2 Search

| 项 | 口径 |
|---|---|
| 接口 | `POST log-viewer/api/v1/rule_info/page`（同功能 1 的检索接口） |
| 结果去向 | 写入 **Source Rule Info 列表**（§2.3） |
| 前置校验 | 点 `Search` 时先校验：**Environment 为空 / TID 为空 / 时间不合法 → 拦住，不发请求** |

### 2.3 Source Rule Info 列表

| 项 | 口径 |
|---|---|
| 形态 | 分页列表，回显本区 `Search` 的结果 |
| 条数 | **不假设 `TID` 只出一条** —— 命中几条就出几条 |
| 列 | 照 `01` §3.2 那套：恒显 14 列 → 可隐藏 3 列 → `EXEC_STATUS`（可选）→ 动态耗时列（**无 `Server Hang` 列**，本功能不消费 Hang 定） |
| 分页 | 同 `01` §3.1：默认每页 20 条，档位 20 / 50 / 100 |
| 行内呈现 | 同 `01` §3.2–§3.5：`Rule Result = CANCELRULE` 单元格标红、多值字段「首值 + 角标」、耗时列单位秒 |
| 排序 | 按 **`Start Time` 正序**（旧 → 新）—— 与 Target 列表相反 |
| 选中 | **单选 1 条** —— 选中的这条即 `Source` |
| 列设置 | **不在本列表单独设** —— 与 Target 列表共用一份，见 §2.4 |

### 2.4 与 Target 列表的列联动

| 项 | 口径 |
|---|---|
| 联动对象 | Source 列表 ⇄ Target 列表 |
| 联动范围 | **非恒显列**：可隐藏三列（Total Cost Time / Item Cost Summary / UnAccounted Cost）、`EXEC_STATUS`、动态耗时列 |
| 列设置入口 | **只做一份** —— 勾选 / 取消一次，两个列表**同时变**；列的**顺序也共用** |
| 横向滚动 | 两个列表**同时左右滚动**（横向滚动位置同步） |
| 恒显 14 列 | 两边固定一致，不参与联动 |

> 引申：因为列集合与顺序共用，两个列表的列位天然对齐 —— 这是「同时左右滚动」能成立的前提。

### 2.5 列表下方按钮

| 项 | 口径 |
|---|---|
| 按钮 | **只有 `Export` 一个** —— 不设 `Rule Log` / `Full Log`（本功能的日志查看在对比区，不落在列表上） |
| `Export` 口径 | 同 `01` §4.1：列表有值即可用；只导**当前显示列** |
| 文件名 | `Source_RuleInfo_<yyyyMMddHHmmss>.xlsx` —— 加 **`Source_` 前缀**，与 Target 的导出区分 |
| 列设置入口 | 与 Target 列表**共用一份**（§2.4），不单独设 |

## 三、Target 区（好的那条）

### 3.1 启用门禁

| 项 | 口径 |
|---|---|
| 先决条件 | **Source 列表选中 1 条之后**，Target 区才可用 |
| Source 未选中 | Target 区**所有条件与按钮一律禁用**（置灰，不可填、不可点） |
| 与 Source 的关系 | Target 的筛选**建立在已选中的 Source 行之上** —— 先定 Source，再按 Source 去筛 Target |

### 3.2 开关（Same X）

Target 区最上面是一组「Same X」开关，共 **7 个**，逐一对应 Source 行的同名字段：

| # | 开关 | 含义 | 对应块文档字段 |
|---|---|---|---|
| 1 | Same Environment | 与选中的 Source 保持相同的环境名 | `ENV` |
| 2 | Same Host IP | 与选中的 Source 保持相同的 IP 地址 | `HOSTIP` |
| 3 | Same ServerID | 与选中的 Source 保持相同的 Server ID | `SERVER_ID` |
| 4 | Same EQP | 与选中的 Source 保持相同的 EQP ID | `EQPID` |
| 5 | Same Carrier | 与选中的 Source 保持相同的 Carrier | `CARRIERID` |
| 6 | Same Lot | 与选中的 Source 保持相同的 Lot ID | `LOTID` |
| 7 | Same Rule Result | 与选中的 Source 保持相同的 Rule Result | `RULE_RESULT` |

**7 个开关进页面时默认全部关闭**；关闭即该字段不参与过滤（见 §3.3）。

### 3.3 条件与时间

**Environment**

| 项 | 口径 |
|---|---|
| `Same Environment` 未勾选 | Target 自己的 Environment 下拉**可用** —— 候选接口与 Source 区相同（`GET log-viewer/api/v1/env/list`） |
| `Same Environment` 勾选 | 值直接取**选中那条 Source 行的 `ENV`** |
| 必填 | **是** |

**时间**

| 项 | 口径 |
|---|---|
| 控件 | Target 区**有自己的 Start Time / End Time 两个时间选择器** —— 与 Source 区的时间各自独立、互不影响 |
| 必填 | **是**（默认不能为空） |
| 默认值 | 与 Source 区一致：结束 = 当前时刻、开始 = 当前时刻 − 1 小时 |

**其余 6 个开关（Host IP / ServerID / EQP / Carrier / Lot / Rule Result）**

| 项 | 口径 |
|---|---|
| 未勾选 | 该字段**不参与 Target 的过滤** |
| 勾选 | 取**选中那条 Source 行的同名字段值**作为 Target 的过滤条件 |

### 3.4 恒随 Source 的项 / 不参与的项

| 项 | 口径 |
|---|---|
| Rule Name | Target 区**不设该条件** —— 过滤时**恒带**选中 Source 行的 `RULENAME`（无开关，不可改） |
| TID | Target 区**不设该条件**，**不参与** Target 的过滤（可以与 Source 不同） |

### 3.5 Source 变化时的清理

| 触发 | 处理 |
|---|---|
| Source 换选另一行 | **清空 Target 区** —— 条件复位到初始态、结果列表清空、7 个开关回到全关 |
| Source 取消选中 | 同上 |

### 3.6 搜索区

| 项 | 口径 |
|---|---|
| 形态 | 一个 `Search` 按钮，由 `Deep Search` 开关切换检索模式 |
| `Deep Search` 进页面默认状态 | **打开** —— 默认走深度检索 |
| `Deep Search` 关闭 | 执行**快速检索** —— 结果**只输出第一行** |
| `Deep Search` 打开 | 执行**深度检索** —— 结果**按分页输出多行** |
| 两者的必然差异 | **结果条数** —— 快速只输出第一行，深度按分页输出多行 |
| 两者的共同点 | **检索条件与排序方法完全相同**，只是输出条数不同；时间区间一律用 **Target 自己的 Start Time / End Time**（§3.3），与 Source 的时间无关 |

> 界面**不设**「搜索耗时上限」输入项（原稿的检索超时保护归后端请求超时，不进界面）。

**快速检索口径**

| 项 | 口径 |
|---|---|
| 用的条件 | 恒带的 `RULENAME` + 勾上的 `Same X` 字段 + 本区指定的 `Environment` |
| 时间范围 | **Target 自己的 Start Time ~ End Time** |
| 排序 | 按 `Start Time` **倒排** |
| 排除 | **排除 Source 那一行** |
| 结果 | 取排序后的**第一行** |
| 列表 | Target 列表**默认选中这一行** |

**深度检索口径**

| 项 | 口径 |
|---|---|
| 用的条件 | 同快速检索 |
| 时间范围 | **Target 自己的 Start Time ~ End Time** |
| 排序 | 同快速检索（按 `Start Time` 倒排） |
| 排除 | **排除 Source 那一行** |
| 结果 | **多行**，走分页列表 |
| 列表 | **不默认选中** —— 由用户自己在列表里选 1 行 |

### 3.7 Target Rule Info 列表

| 项 | 口径 |
|---|---|
| 形态 | 分页列表，回显本区 `Search` 的结果 |
| 列 | 与 Source 列表**同一套**（`01` §3.2）：恒显 14 列 → 可隐藏 3 列 → `EXEC_STATUS`（可选）→ 动态耗时列（**无 `Server Hang` 列**） |
| 分页 | 同 `01` §3.1：默认每页 20 条，档位 20 / 50 / 100 |
| 行内呈现 | 同 `01` §3.2–§3.5：`Rule Result = CANCELRULE` 单元格标红、多值字段「首值 + 角标」、耗时列单位秒 |
| 快速检索后 | 只有 1 行，**默认选中该行** |
| 深度检索后 | 多行，**不默认选中** —— 由用户自己选 1 行 |
| 排序 | 按 **`Start Time` 倒排**（新 → 旧），同 §3.6 |
| 选中 | **单选 1 条** —— 选中的这条即 `Target` |
| 与 Source 列表的关系 | 列设置**共用一份**、**横向滚动同步**（§2.4） |
| 与 Source 的清理联动 | Source 换选 / 取消选中 → 本列表清空（§3.5） |

### 3.8 列表下方按钮

Target 列表下方共 **3 个按钮**：

| # | 按钮 | 可用条件 | 口径 |
|---|---|---|---|
| 1 | `Export` | 列表有值即可用 | 同 Source 区 §2.5（即 `01` §4.1）；文件名 `Target_RuleInfo_<yyyyMMddHHmmss>.xlsx`（加 **`Target_` 前缀**） |
| 2 | `Download Rule Info` | **Target 列表选中 1 行之后** | 对比块的按钮，见 §4.1 |
| 3 | `Compare Rule Info` | **Target 列表选中 1 行之后** | 对比块的按钮，见 §4.2 |

- 不设 `Rule Log` / `Full Log`。
- 列设置入口与 Source 列表**共用一份**（§2.4），不单独设。
- 因 §3.1 门禁（Source 未选中 → Target 全区禁用），这 3 个按钮在 Target 未启用时同样置灰。

## 四、对比区

### 4.1 Download Rule Info

| 项 | 口径 |
|---|---|
| 位置 | Target 列表下方（§3.8） |
| 可用条件 | **Target 列表选中 1 行之后**可用 |
| 下载的是谁 | **Source 那条** —— 用**选中 Source 行的块 `id`**（列表出参里的 `id` 字段，值 = 块 `_id`，**不出列**） |
| 接口 | **`POST log-viewer/api/v1/rule_info/rule_log`** —— **入参与 `full_log` 完全相同**（都是 `id` = 块 id） |
| 与 `full_log` 的区别 | 只在产物：本接口下 **Rule 日志**；`full_log` 下该块涉及的**全部文件**（`.zip`） |
| 产物 | **一个 `.log` 文件** |
| 文件名 | **`<RuleName>_<Start 时间戳>.log`** —— 取选中 **Source 行**的 `RULENAME` 与 `START_TIME` |
| 交互 | 点一次 = 调一次下载接口 |

### 4.2 Compare Rule Info

| 项 | 口径 |
|---|---|
| 位置 | Target 列表下方（§3.8） |
| 可用条件 | **Target 列表选中 1 行之后**可用 |
| 形态 | **左右比较**（形同 Beyond Compare）：**左栏恒为 Source、右栏恒为 Target** |
| 纵向分区 | **上下两个比较框** —— **上框**比**请求消息**、**下框**比**完整日志** |
| 取数 | 点 `Compare` 后，用**选中 Source 行的块 `id`** 与**选中 Target 行的块 `id`**（列表出参里的 `id` 字段，值 = 块 `_id`，**不出列**），**分别调 `GET log-viewer/api/v1/rule_info/detail`**（功能 1 的 `Rule Log` 弹窗那个接口），**游标分页拉完各自请求的完整日志**（`finished = true` 为止） |
| 上框内容 | **首行（消息行）** —— 各自日志里**自上而下第一条**含 `FwEventManager:message to process: :>>L` 或 `FwEventManager:message to process: :>>T` 的行；按 `06-附录A-块首行解析方案.md` **解成一个 KV 集合**后左右比对，见下「上框：请求 message 比对」 |
| 差异标注 | **要标** —— **两个框里两侧不一样的地方都做标记**（颜色与样式归原型 SKILL） |
| 下框内容 | **首行之外的其余日志原封不动**放入下框，左右比对，见下「下框：完整日志比对」 |
| 首行怎么认 | 块 `id` 只标**到块**、标不到行；日志原文里**没有行标识字段** —— 首行只能**按标志串自己认**（`:>>L` / `:>>T`） |

> Source 与 Target 各自独立取数、各自成栏 —— 左栏全部来自 Source，右栏全部来自 Target。

**上框：请求 message 比对**

| 项 | 口径 |
|---|---|
| 取哪一行 | 在**各自的日志**里，取**自上而下第一条**「包含 `FwEventManager:message to process: :>>L` 或 `FwEventManager:message to process: :>>T`」的行 —— 即该块的**首行（消息行）** |
| 怎么解析 | 按 `06-附录A-块首行解析方案.md` 解出**一个 KV 集合**（XML 形态再经该附录 §三的 XML 解析）：`:>>L` 走该附录 一 ~ 三；`:>>T` 走该附录 §四（只出 `ruleName` 一对） |
| 摆放 | **左右并排、共一张表、三列** —— ① **Key** ② **Source 中该 Key 的值** ③ **Target 中该 Key 的值** |
| 行怎么来 | 两侧的条目**按 Key 对齐后摆进同一张表**：Key 相同的**合到一行**；**只有一侧有的 Key 仍单独占一行**，另一侧的值**留空** |
| 同 Key 怎么判 | **按解析出的原 Key 名严格相等** —— **不**按别名表归一（`USER` 与 `USERID` 算两个 Key，各占一行、互相留空） |
| 摆哪些键 | **解析出多少摆多少** —— 含动态键条目（`04` §7.4 样例 A 里的 `FPB08765`、`A672780` 这类，键本身是业务对象 ID）；它们**留在 KV 集合里**，只是不入块文档（`06-附录A` §〇） |
| 行序 | **按 Key 名的字典序**排 |

**XML 形态那一侧**（`06-附录A` 里 `K = XMLDATA` 的情形）

| 项 | 口径 |
|---|---|
| 摆什么 | **只保留 XML 数据** —— `msgTag` / `ruleName` / `XMLDATA` 这些 KV **一概不摆** |
| 怎么换行 | XML 格式化后**每个标签各占一行**：**开标签一行、闭标签一行**（`<msg>` 一行、`</msg>` 一行） |
| 列结构 | **三列，同 KV 形态** —— ① **标签名** ② **Source 中该标签的值** ③ **Target 中该标签的值** |
| 行怎么来 | **按标签名对**：同名标签合到一行；只有一侧有的标签仍单独占一行、另一侧留空 |
| 结构行 | **不带值的结构行照占一行**（`<msg>`、`<msgHeader>`、`</msgHeader>`、`</msgBody>`、`</msg>` 这些），第二、三列留空 |
| 值挂哪行 | 值填在**开标签那一行**（`<txId>` 行填值，紧跟的 `</txId>` 行只作结构） |

**两侧形态**：同一个 Rule 的两条日志**一般同为一种形态**（要么都 XML、要么都 KV）—— **不另设混合形态的对齐规则**。

> **本节的解析在 UI 端自己实现** —— 复用 `06-附录A-块首行解析方案.md` 的**同一套算法**（该附录本就写明两端一致：派生层建块时跑、前端拉回块首行后复盘时跑），**不是**调用派生层拿解析结果。前端照该附录自己跑一遍，产出与派生层一致的 KV 集合，故本节不另立解析口径。

**下框：完整日志比对**

| 项 | 口径 |
|---|---|
| 文本框 | 左右两个，都复用 `01` 的 **Rule Info Detail 弹窗那个日志文本框**（同一套呈现：按行原文、长行自动换行） |
| 左右栏 | **左 = Source、右 = Target** |
| 初始加载 | 打开后两侧各自拉第一页（`detail` 首次调用：`lastFingerprint` / `lastOffset` 留空） |
| 游标 | **两侧各自独立** —— 各自持有自己的 `(lastFingerprint, lastOffset)`，互不影响 |
| 滚动 | **联动滚动** —— 按**滚动偏移同步**：一侧滚多少，另一侧跟同样偏移；短的一侧先到底就停在底、长的一侧继续跟着 |
| 行怎么对 | **行号逐行对** —— 第 N 行对第 N 行；两侧行数不一致时，短的一侧**留空行补齐** |
| 行号怎么算 | **按原始日志行算** —— 长行折行只影响视觉、**不算新行**；行号列与差异标注都按**原始行号**对齐（视觉上不强求两侧同一原始行落在同一高度） |
| 触发时机 | **提前预取** —— 距已加载内容的末位**还剩约 20 行**（按原始行计）即触发拉下一页 |
| 触发后拉谁 | **不看是谁触发的** —— 检查**两侧上一轮的 `finished`**：为 `false` 的**都要继续拉下一页**；已为 `true` 的**不再拉** |
| 例 1 | Source 先滚到底，此时两侧上一轮 `finished` 都是 `false` → **两侧各调一次接口**，各追加一页 |
| 例 2 | Target 滚到底但 Target 已完成（`finished = true`），Source 未完成 → **只拉 Source** |
| 追加方式 | 新拉回的日志**追加到各自文本框的尾部**，不覆盖、不重排 |
| 终止 | **两侧都 `finished = true`** 后，再滚到底不再触发 |
| 重开 / 换选 | **清空重取** —— 换选 `Source` 或 `Target` 行、或再点一次 `Compare` 时，两侧已加载内容清空、游标复位，**都从第一页重新拉** |
| 同步的解除 | 一旦某一侧 `finished = true` **且已滚到底**，**即解开偏移同步** —— 之后两侧各自滚动、互不影响（本次对比内不再恢复；换选 / 重开走「清空重取」） |

### 5.3 沿用 `01` 的接口：本功能的填参差异

**`rule_info/page`**（总表第 4 条）在本功能里**调两次**，`parameters` 只填本区的条件：

| 调用 | `parameters` 填什么 |
|---|---|
| Source 的 `Search` | `env` + `startTime` / `endTime` + `ruleName`（非必填，可空）+ `tid`（§2.1）；`descTime = false`（按 `Start Time` 正序，§2.3） |
| Target 的 `Search` | `env`（未勾 `Same Environment` 时取本区下拉，勾了取选中 Source 行的 `ENV`）+ `startTime` / `endTime`（Target **自己的**时间，§3.3）+ `ruleName`（**恒带**选中 Source 行的 `RULENAME`，§3.4）+ 勾上的 `Same X` 字段；`descTime = true`（按 `Start Time` 倒排，§3.6） |

- 其余键本功能一并**不传**（不设那些条件）。
- `pageIndex` / `pageSize` 同 `01`：点 `Search` 传 `1`，每页默认 `20`，档位 `20 / 50 / 100`。
- 快速检索（`Deep Search` 关）只取返回的**第一行**；深度检索（开）**多行分页**（§3.6）。

### 5.4 本功能新增：`rule_info/rule_log`

| 项 | 内容 |
|---|---|
| 方法 | `POST` |
| 入参 | `id=块 id` —— 取选中 **Source 行**的列表出参 `id` 字段（值 = 块 `_id`，不出列，§4.1）；**与 `rule_info/full_log` 的入参完全相同** |
| 出参 | **一个 `.log` 文件** —— 直接下载，不走统一响应包 |
| 文件名 | `<RuleName>_<Start 时间戳>.log` —— 取选中 **Source 行**的 `RULENAME` 与 `START_TIME`（§4.1） |
| 与 `full_log` 的区别 | **只在产物**：本接口下 **Rule 日志**（这一次执行的日志）；`full_log` 下该块涉及的**全部文件**（`.zip`） |
