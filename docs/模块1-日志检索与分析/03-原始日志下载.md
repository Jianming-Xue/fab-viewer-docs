## 一、功能定位

| 项 | 内容 |
|---|---|
| 干什么 | 按条件搜出**日志文件**（不是块、不是行），列表多选后**整文件下载**（文件级还原） |
| 页面布局 | 自上而下两段：**上＝搜索区**、**下＝结果列表**（含 `Download` 按钮） |
| 行粒度 | **一个文件一行** —— 搜索窗口内有命中行的文件才进列表；聚合键 = `ENV + HOSTIP + LOG_FINGERPRINT`（一个指纹 = 一个物理文件，永不复用，04 §5.2.4） |

**与 Halo 的关键差别**

| 维度 | Halo（旧） | 新方案 |
|---|---|---|
| 日志存放 | **文件系统** | **OpenSearch** |
| 交互流程 | 查询 → 列表展示 → 从列表下载 | 查询 → **文件列表**（多选）→ 下载 |
| 下载内容 | 原始日志文件 | **文件级还原**：该文件在索引里的全部行，按 `LOG_OFFSET` 拼回文件形态（04 §5.2.4） |
| 产物 | 原始文件 | 按【环境 → Host IP → Server Category】分目录的 `.zip`（§五） |

**与模块 1 另外两个下载入口的关系**（同一套还原能力的三个入口）：

| | 01 · Full Log | 01 · 弹窗「全量下载」 | 03 · 本功能 |
|---|---|---|---|
| 入口 | 选中**块** | 选中**块** | 按条件搜出**文件**，多选 |
| 下载什么 | 该块涉及的全部文件（每文件一个 `.log`，zip） | 本块自己的全部行（一个 `.log`） | 选中文件的**全部行**（每文件一个 `.log`，zip） |
| 底层 | 文件级还原 | 执行级还原 | 文件级还原 |
| zip 内命名 | `LOG_FILE` 原值（单块文件少，不歧义） | — | `环境-类别-首行时间`（批量下载防重名，§五） |

## 二、搜索区（5 个条件，控件与候选接口照搬 `01`）

| # | 控件 | 必填 | 取值来源 | 过滤行文档字段 | 不填 / 不选 |
|---|---|---|---|---|---|
| 1 | Environment | 否 | 进页面调 `GET /api/v1/env/list` | `ENV` | 不过滤 |
| 2 | Host IP | 否 | 进页面调 `GET /api/v1/ipaddress/list`（不带参）；Environment 选值后带 `environment` 重取 | `HOSTIP` | 不过滤 |
| 3 | Server Category | 否 | 进页面调 `GET /api/v1/server_category/list` | `SERVER_CATEGORY` | 不过滤 |
| 4 | 开始时间 | **是** | 时间选择器，精确到分钟 | `LOG_TIME`（区间下界） | — |
| 5 | 结束时间 | **是** | 同上 | `LOG_TIME`（区间上界） | — |

- **无 Server Number、无折叠区**；本功能不含 `01` 的其余条件。
- **联动**（同 `01` §2.7）：Environment 变更 → 重取 Host IP 候选并清空已选。
- **时间细则**（同 `01` §2.2）：默认 结束 = 当前时刻、开始 = 当前时刻 − 1 小时；`开始 ≤ 结束`（**同分钟合法**，同 `01`）且差值 ≤ 1 天；清空一端自动补另一端；即时校验。
- **按钮**：`Search`（校验通过后查第 1 页）/ `重置`（条件回默认、结果列表清空、不自动查询）——同 `01` §2.5。

## 三、结果列表

| 项 | 口径 |
|---|---|
| 行粒度 | 一个文件一行（§一）；同一文件跨页稳定（聚合键不变） |
| 列（按序） | Environment、Host IP、Server Category、Start Time、End Time、File Name |
| `Start Time` / `End Time` | **该文件中命中搜索条件那些行**的 `LOG_TIME` 最小 / 最大值 —— 它是「这个文件为什么被搜出来」的证据（注意：不是该文件全部行的时间范围） |
| `File Name` | 行文档 `LOG_FILE` 原值（含滚动序号，如 `DT_PRD_MBX.FABsrv.log.1`） |
| 分页 | 同 `01` §3.1：默认 20 条，档位 20 / 50 / 100，分页组件始终显示，共 N 条 |
| 行选择 | **多选**（复选框，与功能 1 / 2 的单选不同） |
| 跨页选择 | **翻页保留**已选；重新 `Search` / `重置` 一律清空 |
| 空结果 / 加载中 | 同 `01` §3.7：空结果时 `Download` 不可用；加载中列表显示动画、`Download` 置灰 |

## 四、Download

| 项 | 口径 |
|---|---|
| 位置 | 结果列表下方，唯一按钮 |
| 可用条件 | **已选中 ≥ 1 行**；空列表 / 未选中不可用 |
| 入参 | 选中行的 `id`（`page` 出参 `contents[].id`，**不出列**）数组 |
| 下载什么 | 每个选中文件的**全部原始日志**（该指纹在行索引里的全部行 —— **不只命中行**；窗口只负责把文件找出来） |
| 后端怎么做 | 逐个 `id` 解码 → `(ENV, HOSTIP, LOG_FINGERPRINT)` → 四 `term` 查行索引 → 堆内按 `LOG_OFFSET` 升序拼回 → 每 `id` 一个 `.log` → 全部打包 `.zip`（文件级还原，04 §5.2.4） |
| 单次上限 | **不设**（后端流式生成 zip） |
| 产物 | 命名 / 目录 / zip 名见 §五 |

## 五、下载产物（沿用 2026-09-14 冻结口径，归组键由「文件名 + inode」改为指纹）

### 5.1 `.log` 文件命名

**`环境名` + `Server Category` + `日志首行时间戳`**，用 `-` 连接：

| 项 | 说明 |
|---|---|
| 不用指纹 / `id` 当文件名 | 无业务含义，人看不出是什么 |
| 不用原始文件名单独命名 | 会**重名**（多台 Server 上同名文件很常见） |
| Host IP 不进文件名 | 放在目录层级里（§5.2） |
| 时间戳格式 | 归一化 `yyyyMMddHHmmss`，取**该文件还原后的第一行**的时间（文件全部行里最早的一行 —— 不是搜索窗口内首行） |
| 撞名兜底 | 同目录内首行时间戳相同 ⇒ 时间戳后追加 `.1`、`.2`…（从 `.1` 起，**不覆盖**） |

**示例**：`PIRUN-FAB-20260914103000.log`

### 5.2 zip 内目录

按 **环境 → Host IP → Server Category** 三级分目录：

```
PIRUN/
  ├── 10.20.30.40/
  │     └── FAB/
  │           ├── PIRUN-FAB-20260914103000.log
  │           └── PIRUN-FAB-20260914104300.log
  └── 10.20.30.41/
        └── QUERY/
              └── PIRUN-QUERY-20260914103210.log
```

### 5.3 外层 zip 命名

由**本次搜索条件**直接拼出：填了值的条件按表单顺序（环境 → Host IP → Server Category → 时间）用 `_` 串起，未选的不拼；时间为 `开始-结束` 一段（`yyMMddHHmm`，End 与开始同年省略年份，跨年才带）。

| 本次填了什么 | zip 名 |
|---|---|
| 只填时间（2026-09-14 10:00 ~ 11:00） | `2609141000-09141100.zip` |
| + 环境 `PIRUN` + `FAB` | `PIRUN_FAB_2609141000-09141100.zip` |

> 外层 zip 与内层 `.log` 两套口径：zip 名表达「这次下了什么范围」，`.log` 名表达「这是哪个文件」。

## 六、接口清单

外壳一律走**统一响应包**（`{ "success": true, "errCode": 0, "data": ... }`，`01` §5.1）；文件下载除外。候选类接口（1~3 号）**沿用 `01` §5.3 第 1 / 2 / 3 条**，不重复定义。

### 6.1 `GET /api/v1/raw_log/page`

| 项 | 内容 |
|---|---|
| 方法 | `GET`（条件走 URL 参数） |
| 入参 | `pageIndex`（进页面传 `1`）、`pageSize`（默认 `20`）；条件五个全可选——`env`、`hostIp`、`serverCategory`（等值）、`startTime` / `endTime`（`yyyyMMddHHmm`，同 `01` 的时间格式，打 `LOG_TIME`） |
| 出参 | `data` = 分页格式（同 `01` §5.3-9）：`totalPage` / `total` / `pageIndex` / `pageSize` / `contents[]` |

```json
{
  "totalPage": 1, "total": 3, "pageIndex": 1, "pageSize": 20,
  "contents": [
    {
      "id": "<文件 id：base64url(ENV|HOSTIP|LOG_FINGERPRINT)，服务端编码可逆，不出列>",
      "env": "<ENV>",
      "hostIp": "<HOSTIP>",
      "serverCategory": "<SERVER_CATEGORY>",
      "startTime": "<该文件命中行的最早 LOG_TIME，yyyy/MM/dd HH:mm:ss.SSS>",
      "endTime": "<该文件命中行的最晚 LOG_TIME>",
      "fileName": "<LOG_FILE 原值>"
    }
  ]
}
```

**`id` 的口径（2026-10-10 定）**：
- 内容 = `base64url(ENV + "|" + HOSTIP + "|" + LOG_FINGERPRINT完整64hex)`——对客户端是**不透明文件 id**（与 `01` 的块 `id` 同款模式），签名不以明文出现；
- **必须含 ENV + HOSTIP**：指纹 = 文件头内容哈希，**跨机器会撞**（两台机器同 Server 同首行即同指纹），只在同环境同主机内才是唯一文件身份 —— 后端解码后按四 `term` 查行；
- **编码完整指纹不截短**：行查询 `term` 要命中完整 64 hex；
- 同一文件 `id` 恒定（指纹不随滚动改名变）；两个文件代 = 两个指纹 = 两个 `id`，列表天然两行、下载不混。

### 6.2 `POST /api/v1/raw_log/download`

| 项 | 内容 |
|---|---|
| 方法 | `POST` |
| 入参 | `{"ids": ["<文件 id>", "..."]}`（选中行的 `contents[].id`，至少 1 个） |
| 出参 | **`.zip` 文件直接下载**，不走统一响应包（同 `01` `full_log` 先例）；命名 / 目录见 §五 |
| 行为 | 每 `id` 独立还原（互不影响）；单个 `id` 解码失败 / 查无行 ⇒ 整单失败返回错误（不部分下载） |
