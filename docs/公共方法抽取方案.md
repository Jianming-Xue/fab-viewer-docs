## M01 `FetchLogMonitorSrvCategoryFromSystemMisc()` — 启动读 ServerCategory 白名单

**方法名**：`M01_FetchLogMonitorSrvCategoryFromSystemMisc()`

**入参**：无。

**出参**：`string[]`。

**逻辑**

1. 用配置 item `log.monitor.servercategory` 读配置。
2. 配置的 `valueType` 不为 `Json` 时，返回值为空（`[]`）。
3. `valueType` 为 `Json` 时，先对 `value` 解析成字符串数组：无法解析、或解析得到的数组为空，则进入第 4 步；否则直接输出解析得到的字符串数组。
4. 对 `defaultValue` 解析成字符串数组：解析失败则输出为空（`[]`）；解析成功则输出得到的字符串数组，**无论其是否为空**。

## M04 `FetchMESRuleFullLogs()` — 按块取全部行并还原写入顺序

**方法名**：`M04_FetchMESRuleFullLogs()`

**入参**

| 参数 | 取值 | 说明 |
|---|---|---|
| `blockId` | string | 块索引中块的 `_id` |

**出参**：`MESRuleRawLogEntity` 对象。

| 字段 | 类型 | 说明 |
|---|---|---|
| `RuleName` | string | 块上的 `RULE_NAME` |
| `Tid` | string | 块上的 `TID` |
| `StartTime` | datetime | 块上的 `START_TIME` |
| `RawLogs` | Map<number, string> | K = M05 赋予的 `OrderNumber`，V = 该行 `LOG_RAW`；按 K 升序即写入顺序 |

**逻辑**

1. 入参 `blockId` 为空时，方法报错。
2. 以 `blockId` 作为块索引的 `_id` 取块信息，取回字段：`ENV` / `HOSTIP` / `SERVER_ID` / `system.name`、`START_TIME` / `END_TIME`、`START_LINE_ID` / `END_LINE_ID`、`RULE_NAME`、`TID`。
3. 块信息为空时，方法报错。
4. 用块上的四个 `term` + `START_TIME` / `END_TIME` 查行索引：`START_TIME` / `END_TIME` 与行上的 `LOG_TIME` 比较，**上下界均为闭区间**。取回字段：`LOG_FINGERPRINT` / `LOG_OFFSET` / `LOG_RAW` / `_id`。分页取全后转第 5 步重排。
5. 把第 4 步行结果映射成 M05 入参 `lines`：`_id → LineId`、`LOG_FINGERPRINT → LogFingerPrint`、`LOG_OFFSET → LogOffset`，`OrderNumber` 置 0；**不传 `LOG_RAW`**，原文由本方法按 `LineId` 自行保留。调 M05：`tieMode` 固定 `NO_TIE`，**不传 `knownOrder`**。取回出参 `MESRuleLineLogEntity[]`（每行已带从 1 起的 `OrderNumber`）与 `knownOrder`（本方法不使用，不进 M04 出参）。
6. 在 M05 返回的 `lines` 中按 `LineId` 定位 `START_LINE_ID` 与 `END_LINE_ID` 两行，取两行 `OrderNumber` 之间的全部行（**含两端**）；`OrderNumber` 保持 M05 赋值，**不重新编号**。
7. 按裁剪后各行的 `OrderNumber` 建 K-V：Key = `OrderNumber`，Value = 本方法第 4 步按该行 `LineId` 取回的 `LOG_RAW`，组成出参 `RawLogs`；`RuleName` / `Tid` / `StartTime` 分别取块上的 `RULE_NAME` / `TID` / `START_TIME`。

## M05 `ReorderMESRuleRawLogs()` — MES 规则行日志重排（输出行顺序编号与指纹顺序）

**方法名**：`M05_ReorderMESRuleRawLogs()`

**入参**

| 参数 | 取值 | 说明 |
|---|---|---|
| `lines` | `MESRuleLineLogEntity[]` | 待排序行集合。对象字段：`LogFingerPrint` / `LogOffset` / `LineId` / `OrderNumber`（**不含原文，原文由调用方自行组织**）；**入参对象的 `OrderNumber` 恒为 0** |
| `tieMode` | `WITH_TIE` / `NO_TIE` | 排序口径开关 |
| `knownOrder?` | Map<number, string> | 可选，不传视为数量 0。K = 顺序编号（从 1 开始），V = `LogFingerPrint` 字符串 |

**出参**：排序后的 `MESRuleLineLogEntity[]`（`OrderNumber` 从 1 开始逐行赋值）+ 最终的 `knownOrder`。

**逻辑**

1. 提取 `lines` 中所有 `LogFingerPrint` 并去重，得指纹集合。
2. 指纹集合数量 = 1：直接按 `LogOffset` 排序；从 1 开始生成 `knownOrder`（唯一指纹的顺序编号为 1），并逐行赋 `OrderNumber` 后输出。
3. 指纹集合数量 > 1，按 `tieMode` 分支：
   - `NO_TIE`，或 `WITH_TIE` 但传入的 `knownOrder` 数量 ≤ 1：对集合中每个 `LogFingerPrint`，从**行文档**取该指纹 `LogOffset` 最小那行的 `LogTime`（入参实体不带 `LogTime`，须回查行索引），按 `LogTime` 给指纹排序，从 1 开始生成新的 `knownOrder` 用于最终排序。
   - `WITH_TIE` 且传入的 `knownOrder` 数量 > 1：先检查指纹集合是否全部落在传入 `knownOrder` 中。全部落在 ⇒ 不再给指纹排序，直接用传入的 `knownOrder` 做最终排序；有任何一个不在 ⇒ 退回上一条，按各指纹最小 `LogOffset` 行的 `LogTime` 重新排序、生成新的 `knownOrder`。
4. 拿到最终 `knownOrder` 后，对 `lines` 先按 `LogFingerPrint` 分堆 → 堆内按 `LogOffset` 升序（**此时不赋 `OrderNumber`**）→ 堆间按 `knownOrder` 的编号顺序排，得到堆间 + 堆内的完整序列。
5. 对完整序列从 1 开始逐行赋 `OrderNumber` 并输出，同时输出最终的 `knownOrder`。

## M06 `ParseMESRuleInfo()` — 块首行解析（Rule / TXN 分流）

**方法名**：`M06_ParseMESRuleInfo()`

**入参**

| 参数 | 取值 | 说明 |
|---|---|---|
| `ruleMessage` | String | 块首行原始日志，一整行（含时间戳与服务名前缀）；解析方案权威见 `06-附录A` |

**出参**：`MESRuleParsedResultEntity` 对象。

| 字段 | 类型 | 说明 |
|---|---|---|
| `RequestType` | String | `Rule` / `TXN` |
| `KVParameters` | Map<String, List<String>> | 请求头 + `attributes` 合成出的 KV **全集**：固定键与动态键条目都在，K = 键名，V = 值集合 |
| `XMLParameters` | Map<String, List<String>> | `XMLDATA` 解析出的 XML KV；非 XML 形态或解析失败为空 |
| `SpecialFields` | Map<String, List<String>> | 要写进块文档的 7 个业务字段：`RULENAME` / `LOTID` / `EQPID` / `PORTID` / `CARRIERID` / `USERID` / `TID`；按出现顺序追加、同值去重 |

**逻辑**

1. **门禁分流**：看首行标志 `FwEventManager:message to process: :>>L` / `:>>T`，定 `RequestType = Rule` / `TXN`。Rule 走第 2~4 步，TXN 只走第 5 步。
2. **Rule · 剥壳切段**：砍到 `:>>L `（含尾空格）→ 砍第一个空格前的方法名 → 定位 `attributes={` → 从 `{` 起计数扫到归 0，摘出 `attributes` 段，剩下为请求头。全程挂 `inQuote`（`"` 翻转）与 `esc`（`\` 跳下一字符）两个状态位，引号内的 `{` `}` 空格 `=` 一律当字面量、不参与结构判断。
3. **Rule · 合成 `KVParameters`**：请求头用等号定位法（扫所有 `=`，Key 回退到第一个空格、首个起点为 0，Value 到下一个 `=` 的 Key 起点，各剥首尾一对引号）；`attributes` 内部按归 0 切块（每块带 `{}`），剥外层后按**第一个空格**切 Key/Value；`class=ASSOC` 形态声明块去掉前缀后再切，须恰好 2 块、各取块内第二段。请求头 KV 与 `attributes` KV 合成 `KVParameters`。
4. **Rule · XML**：集合里有 `K = XMLDATA` 时，把 Value 交标准 XML 解析器，标签名即 Key（小驼峰、不二次解析），`<txId>` 在 `<msgHeader>` 下、其余在 `<msgBody>` 下，**重复出现的兄弟节点整组不取**，结果进 `XMLParameters`；无 `XMLDATA` 或解析失败 ⇒ 空。
5. **TXN**：砍到 `:>>T` → 取剩余串第一个空格前的 token 作 TxnName → 以 `ruleName = TxnName` 放进 `KVParameters`；其余六个字段无从取起。
6. **`SpecialFields`**：在 `KVParameters` 里按字段配置表查（键名归一化后落标准字段），取到就写、取不到留空；动态键条目（键本身是业务对象 ID）留在 `KVParameters`、**不进** `SpecialFields`。
7. **兜底**：`attributes={` 找不到、计数没归 0、`class=ASSOC` 块切出不是 2 块 ⇒ 整条不解析、七字段留空；`key = value` 空 Key 跳过；块内无空格 ⇒ 值留空；`TXN` 取不到 TxnName ⇒ `RULENAME` 留空。**解析不到一律留空，不打 MISS 标记、不截断**；纯字符串扫描不用正则，两端实现须逐字节一致。

## M07 `FetchMESFileFullLog()` — 按文件指纹取单个文件的全部行

**方法名**：`M07_FetchMESFileFullLog()`

**入参**

| 参数 | 取值 | 说明 |
|---|---|---|
| `fileId` | string | 文件标识，与行文档 `LOG_FINGERPRINT` 匹配 |

**出参**：`MESFileRawLogEntity` 对象集合。

| 字段 | 类型 | 说明 |
|---|---|---|
| `FileName` | string | 行上 `LOG_FILE` |
| `Environment` | string | 行上 `ENV` |
| `HostIPAddress` | string | 行上 `HOSTIP` |
| `ServerCategory` | string | 行上 `SERVER_CATEGORY` |
| `RawLogs` | Map<number, string> | K = 排序后从 1 起的编号，V = 该行 `LOG_RAW` |

**逻辑**

1. 入参 `fileId` 为空时，方法报错。
2. 用 `fileId` 匹配行文档的 `LOG_FINGERPRINT`，分页取全；取回字段：`LOG_FILE` / `ENV` / `HOSTIP` / `SERVER_CATEGORY` / `LOG_RAW` / `LOG_OFFSET`。
3. 结果只有一个 `LOG_FINGERPRINT`，直接按 `LOG_OFFSET` 排序即可，不做分堆。
4. 排序后生成出参对象：`FileName` ← `LOG_FILE`、`Environment` ← `ENV`、`HostIPAddress` ← `HOSTIP`、`ServerCategory` ← `SERVER_CATEGORY`；`RawLogs` 的 Key 为排序后从 1 起的编号、Value 为排序后的 `LOG_RAW`。
